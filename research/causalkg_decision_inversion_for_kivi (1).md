# Inverting CausalKG for Kivi

**Paper:** Utkarshani Jaimini and Amit Sheth, “CausalKG: Causal Knowledge Graph Explainability using interventional and counterfactual reasoning” (2022), [arXiv:2201.03647](https://arxiv.org/pdf/2201.03647).

**Setting used for comparison:** *The Things Kivi Comes to Know* (attached position document). Kivi is a text-based semantic-memory product that retains attributable, revisable work-level facts about one user; excludes sensitive inferences and third-party personal content; distinguishes stated, observed, and hypothesised material; gates disclosure; and exposes provenance and correction controls.

## Reading note

This is a design inversion, not a summary. The paper is a short conceptual framework plus an autonomous-driving illustration. It does **not** specify an implemented end-to-end system, retrieval algorithm, conflict policy, user interface, or empirical evaluation. Where those choices matter, this document says **underspecified**.

Page links below use PDF page numbers (the PDF viewer’s numbering, beginning at 1).

## 2. Forced choices

These are load-bearing because changing them would remove the claimed novelty, invalidate the illustrated reasoning, or materially alter the architecture.

| ID | Why it is load-bearing | What changes if answered differently |
|---|---|---|
| D1 | The paper’s purpose is domain-level causal explainability rather than model-level or correlational explanation. | A provenance or feature-attribution system would be a different contribution and would not support the paper’s claimed “why/what-if” account. |
| D2 | The motivating defect is that a binary cause–effect edge cannot carry mediator and effect structure. | Accepting binary relations removes the need for CausalKG’s hyper-relational representation. |
| D3 | Intervention and counterfactual semantics come from the CBN. | Without a causal formalism, the graph is semantic rather than causal; with cyclic or temporal formalisms, inference and assumptions change. |
| D4 | Treatment–mediator–outcome roles define the causal ontology. | Alternative primitives change both ontology design and which questions the graph can answer. |
| D5 | Storing effect types and magnitudes is how the KG becomes more than a labelled causal graph. | On-demand or external effect storage would separate knowledge representation from estimation and weaken the claimed integrated framework. |
| D6 | RDF-star is the selected mechanism for making causal statements hyper-relational. | Another encoding changes interoperability, query design, and complexity, though not necessarily causal semantics. |
| D7 | The framework begins with an available CBN/domain ontology rather than discovering them. | Learning structure from Kivi’s transcripts would introduce uncertainty, feedback, validation, and revision problems absent from the paper. |
| D10 | The paper’s explanation hierarchy assumes causal domain context should correct association. | If conflicting evidence remains unresolved or association wins, its ice-cream/drowning argument and trust story change materially. |
| D15 | Direct/indirect/total effect decomposition is the concrete content of the representation and driving example. | Other causal queries require different estimands and often different assumptions or graph metadata. |
| D18 | The paper extends the graph from explanation toward downstream learning and planning. | Explanation-only use contains failure impact; action use creates a feedback and safety system the paper does not evaluate. |

For Kivi, D7 and D18 are especially consequential: Kivi’s evidence is an evolving personal transcript stream, and its core promise separates retrieval, disclosure, and action. The paper assumes away both problems.

## 3. Unexamined defaults

These are choices the paper appears to inherit rather than argue for.

| Default | Where it appears | Alternative this line of work rarely foregrounds |
|---|---|---|
| A single authoritative causal graph exists for a context. | The framework requires “a CBN describing the causal relationships” as input. | Store multiple incompatible causal models with explicit sponsors, evidence, and conditions; answer with disagreement rather than forced synthesis. |
| The causal graph is acyclic. | CBN is defined as a DAG. | Model feedback loops and the system’s own interventions explicitly, especially for adaptive assistants. |
| Domain experts’ causal knowledge is legitimate system input without a governance layer. | The ontology/CBN are supplied as domain knowledge. | Treat expert knowledge as a contestable, versioned claim requiring provenance, expiry, and affected-user review. |
| More domain knowledge and a broader search space are beneficial. | The KG is praised for comprehensive search over counterfactual variables. | Purpose-limited ignorance: refuse to represent certain facts or causal hypotheses even when predictive, because retaining or using them violates the relationship. |
| Causal explanation increases trust. | The paper repeatedly links human-understandable causality to trust. | Treat explanation as a tool for calibrated reliance and make it capable of reducing trust; test over-trust and persuasive-but-wrong explanations. |
| Numeric effect metadata is intelligible once attached to graph relations. | Figures associate effect values/types with paths. | Expose assumption sensitivity, identification conditions, uncertainty, and provenance before any point estimate. |
| Ontology classes cleanly fit domain entities. | Generic Treatment/Mediator/Outcome classes extend domain ontologies. | Allow role ambiguity, time-dependent roles, and one entity occupying competing roles across models. |
| Observational data and causal knowledge can be joined after entity/variable alignment. | Figure 2 moves directly from dataset/CBN/ontology to effect estimation. | Treat alignment as probabilistic and user-correctable; retain unresolved mappings instead of collapsing them. |
| A static illustrative graph is an adequate demonstration of reasoning. | The driving use case maps a hand-described collision scenario into CBN/KG figures. | Evaluate longitudinal graph revision under drift, contradiction, deletion, and adversarial evidence. |
| Human-understandable means causal content, not interaction design. | Explainability is defined conceptually; no user interface or comprehension protocol is specified. | Test whether users can inspect sources, contest a claim, understand uncertainty, and recover after an error. |
| Counterfactual reasoning can be discussed independently of actionability and consent. | The paper asks what-if questions about humans and risky systems without an authorization model. | Separate permission to compute, retain, disclose, and act on a counterfactual—as Kivi’s calibration principle requires. |
| “Humans” can be graph entities like physical objects and places. | The KG is said to represent time, space, physical objects, humans, and interactions. | Impose person-specific data rights, sensitive-inference prohibitions, third-party non-retention, and asymmetric edit authority. |

## 4. Questions the paper never faced — raised by Kivi

These are derived from Kivi’s users, constraints, and failure modes, not generic CausalKG limitations.

### Admission and representation

1. When one interaction contains the user’s words and another person’s private information, what should determine which derived facts may cross the write boundary?
2. When a candidate memory is useful but belongs to an excluded sensitive category, should the system drop it silently, retain only the exclusion event, or expose the rejected candidate to the user?
3. When a fact is about another person’s role in the user’s work, what boundary separates permissible work-level residue from impermissible profiling of that person?
4. When the same content could be an entity fact, preference, episode, observation, or hypothesis, what should determine its type and epistemic tier?
5. When a pattern is repeatedly observed but never explicitly confirmed, should repetition increase retrieval priority, disclosure eligibility, neither, or both?
6. When a user confirms a hypothesis, should the stored result preserve the original question and its evidence, replace it with a stated claim, or link both?

### Conflict, revision, and time

7. When a new statement contradicts an old memory, what should determine whether it is a correction, a temporary exception, a time-bounded change, or a different context?
8. When the user says “that’s not me anymore,” how broad should suppression be: exact claim, semantic paraphrases, evidence sources, category, or future derivations?
9. When a user forgets a memory whose source transcript remains, what should prevent the extractor from regenerating it while preserving other legitimate memories from that transcript?
10. When observations age, should decay depend on elapsed time, number of opportunities to re-observe, task frequency, user confirmation, or failure cost?
11. When a corrected memory was already used in earlier outputs or actions, what should remain visible in history, and to whom?

### Retrieval, disclosure, and action

12. When regular dictation and Hey Kivi share lexical/entity data, what should prevent semantic observations or hypotheses from leaking across the structural retrieval boundary?
13. When the system retrieves a prohibited tier, what should be logged or exposed without disclosing the prohibited content itself?
14. When several memories are relevant but disagree in tier, recency, or source authority, what should determine ranking before the permission dial determines disclosure?
15. When a low-permission answer withholds something materially important, should the interface reveal only that something was withheld, its category, its risk, or nothing?
16. When Daari is invoked for one request, what should determine the temporal and conversational boundary after which hypothesis permission closes?
17. When Kivi notices a pattern through its own generated drafts, should those outputs count as evidence about the user, be excluded as self-contamination, or count only after user edits?

### Error, control, and evaluation

18. When Kivi lacks an answer, what evidence threshold should trigger abstention rather than a qualified response or clarification question?
19. When confirmation prompts are budgeted, what should determine “highest value” without steering users toward the system’s preferred model of them?
20. When the user corrects one surface (the response, Why panel, or memory page), what should guarantee atomic propagation across storage, retrieval indexes, caches, and suppression rules?
21. When provenance itself contains third-party personal information, what should the user-facing source view reveal, redact, or summarise?
22. When an excluded candidate is logged to prove the boundary worked, how can the audit log avoid becoming a shadow store of the prohibited content?
23. When Kivi is wrong, what should determine whether the remedy is correction, demotion, forgetting, suppression, abstention, or rollback of an action?
24. When a user changes the persistent Anbu/Koottu setting, should the change affect only future disclosures or also previously generated traces and cached responses?

## 5. Evaluation gap

### What the paper actually measured

The paper reports **no empirical evaluation**. It provides:

- a conceptual three-step framework (CBN + observational data; causal ontology/domain-ontology enrichment; causal-effect estimation);
- an autonomous-driving collision scenario;
- illustrative CBN and CausalKG figures;
- example questions for statistical, contextual, and domain explainability; and
- qualitative claims that the representation supports intervention, counterfactual reasoning, trust, accuracy, reliability, planning, and diagnosis.

It does **not** report a dataset specification, train/test split, implementation, baseline, ablation, query set, correctness metric, calibration, effect-estimation error, retrieval metric, graph-completion metric, explanation-comprehension study, trust calibration, latency, throughput, cost, privacy test, or longitudinal update test. The phrase “estimated using the autonomous driving dataset” appears, but the dataset, estimator, values, assumptions, and evaluation protocol are not specified in the paper’s use-case discussion ([pp. 7–8](https://arxiv.org/pdf/2201.03647#page=7)).

### Decisions its evidence cannot distinguish

Because there is no comparative evaluation, **every substantive choice in D1–D20 is supported as a precedent or argument, not by discriminating evidence**. More specifically:

| Indistinguishable alternatives | Decisions affected | Why they would score the same under this paper |
|---|---|---|
| RDF-star vs reification vs property graph vs relational schema | D2, D5, D6, D14 | No implementation, query workload, interoperability test, storage cost, or user outcome is measured. |
| Expert-authored CBN vs learned/extracted/contested causal models | D3, D7, D10, D20 | The collision graph is illustrative; structure accuracy and authoring cost are never evaluated. |
| Total/direct/indirect effects vs other causal estimands | D4, D5, D15 | No ground-truth intervention or counterfactual benchmark tests whether the selected estimands answer users’ actual questions. |
| Causal explanation vs provenance, examples, uncertainty, or feature attribution | D1, D16 | No user study measures comprehension, action quality, calibrated reliance, or over-trust. |
| Comprehensive KG expansion vs narrow or hybrid retrieval | D12, D13 | No retrieval corpus, relevance judgments, recall/precision, latency, or answer accuracy is reported. |
| Point effect values vs distributions with assumptions and uncertainty | D5, D14, D17 | No calibration, interval coverage, sensitivity analysis, or failure threshold is measured. |
| Replace vs version vs coexist vs user-adjudicate contradictions | D10, D11, D19 | The example is static; no conflicting or changing evidence enters it. |
| Retain-all vs minimisation, sensitive exclusion, and third-party non-retention | D8, D9, D14 | Privacy, consent, leakage, deletion, and auditability are outside the evaluation. |
| Answer-always vs qualify, ask, or abstain | D13, D17 | There are no unanswerable queries, uncertainty labels, or costs for confident error. |
| Explanation-only vs using causal knowledge to plan or act | D18 | No downstream task, intervention, feedback-loop, or harm measure is evaluated. |
| Global/domain/context/user/episode-scoped graphs | D20 | No cross-context leakage, transfer, personalisation, or context-composition test exists. |
| Static graph vs temporal revision, decay, and suppression | D11, D19 | No longitudinal data or update operation is shown. |

### What that means for Kivi’s stated demonstration claims

The paper provides **no evidence** that can choose among Kivi’s open storage/retrieval options (embeddings, structured query, or hybrid), nor evidence for extraction timing, decay windows, confirmation budgets, evidence thresholds, latency, or cost. It also does not test any of Kivi’s seven committed demonstrations: excluded-category dropping, third-party read/not-kept behavior, cross-transcript memory assembly, permission-dependent withholding, evidence-backed abstention, durable non-regrowth after correction, or structural isolation of dictation retrieval.

Accordingly, CausalKG is relevant to Kivi mainly as a map of one possible representational branch—explicit causal structure plus graph-attached effects—not as evidence that this branch is appropriate for personal semantic memory.
