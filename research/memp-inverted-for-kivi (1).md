# Inverting *Memᵖ*: The Design Questions Behind Agent Procedural Memory

This memo inverts Fang et al.'s *Memᵖ: Exploring Agent Procedural Memory* into the decisions that produced it, then tests the assumptions behind those decisions against Kivi's stated position. It maps the space; it does not select answers for Kivi.

## Scope and interpretive boundary

*Memᵖ* studies **procedural memory**: reusable instructions, scripts, trajectories, tool sequences, and recovery tactics for completing analogous tasks. Kivi is primarily designing **semantic memory about one person and their work**: entities, preferences, episodes, observations, and carefully gated hypotheses. The overlap is the memory lifecycle—build, represent, retrieve, use, update, and forget—not the object being remembered. Where the paper offers evidence only for procedural memory, that limitation is stated rather than silently transferring the result.

“Holds for Kivi?” is assessed against *The Things Kivi Comes to Know*, especially its commitments to calibration, non-retention of others, revisability, epistemic tiers, separate dictation and Hey Kivi paths, provenance, abstention, suppression, and decay.

## 2. Forced choices

These are load-bearing in the paper: changing the answer would materially change the reported system or what its results mean.

| Decision | Why it is load-bearing in *Memᵖ* | What remains genuinely open for Kivi |
|---|---|---|
| **F1 — Memory representation (D2/D3): trajectory, script, or both** | This is the main construction ablation. Table 1 shows materially different success and step outcomes, and the combined condition supplies the paper's strongest overall build-policy result. | Whether Kivi's analogous pair is “typed belief + source transcript,” and whether both may enter model context, cannot be inferred from procedural-task results. |
| **F2 — Retrieval key and ranking (D4/D5)** | Table 2 directly varies random, full-query, and keyword/fact keys. Some metrics move substantially—for Qwen hard-constraint score, 8.43 (random) to 12.66 (AveFact)—so key construction affects results. | Kivi's decisive signals include tier, user authority, time, status, subject, project, and surface; none appears in the ablation. |
| **F3 — Retrieval quantity (D6)** | The paper reports a rise, plateau, and decline as retrieved memory count increases. Context competition and irrelevant memories can reverse gains. | Kivi must set both a retrieval breadth and a separate disclosure/influence breadth. The paper varies only the former. |
| **F4 — Update supervision (D10/D13)** | The sequential-learning claim depends on append, success filtering, and especially failure-guided adjustment/reflection. The paper attributes its best late-stage trend to error-corrective updating. | Kivi lacks objective reward and treats explicit user correction as privileged. What event licenses a semantic-belief change remains unsupported. |
| **F5 — In-place revision after failure (D9)** | The “continual refinement” result depends on rewriting retrieved memory using failed experience. If failures were merely logged or competing variants preserved, the tested system and learning curve would differ. | For Kivi, failure may implicate retrieval, permission, generation, or the belief itself. The paper does not isolate these causes. |
| **F6 — Gold/success-biased memory admission (D1)** | Offline results depend on filtered gold trajectories, and online Validation depends on successful-task filtering. Noisy or harmful memories would alter both store quality and retrieval. | Kivi's admissibility is not reducible to success: a correct response can contain forbidden third-party content, and an unsuccessful response can still contain a true user statement. |
| **F7 — Prompt-context use before execution (D7/D8)** | All reported benefit relies on injecting retrieved memory into the acting model's context. A checker-only or gated-use architecture might produce different performance. | Kivi has two contracts: ordinary dictation and Hey Kivi. The paper gives no evidence that one influence policy should serve both. |
| **F8 — Objective reward as memory-quality proxy (D20)** | Reward selects experiences, triggers/validates updates, and defines improvement. Remove trustworthy reward and the paper's autonomous loop loses its supervisory signal; the authors acknowledge this limitation. | Most Kivi truths and preferences have no benchmark reward. LLM-as-judge, mentioned by the paper, would still not supply user authority, consent, or identity correctness. |

## 3. Unexamined defaults

These choices are mostly inherited from agent-memory and benchmark practice. “Alternative nobody tries” means absent from this paper and uncommon in the procedural-memory line it positions itself within; it is not a universal literature claim.

| Default the paper inherits | The unnoticed question | Alternative largely absent from this line of work | Evidence of the default |
|---|---|---|---|
| **The agent owns every trajectory it can observe.** | Who has standing to authorize retention of information inside an execution trace? | A write path that rejects content by subject and consent before any memory candidate reaches storage, even when retention would improve reward. | Full/gold trajectories are stored without ownership fields or subject gates ([Storage & Retrieval](https://arxiv.org/html/2508.06433v2#S4.SS2)). |
| **Helpfulness authorizes use.** | Does relevance grant permission to influence or disclose? | Retrieve broadly, then enforce a separately auditable permission policy over influence and disclosure. | Retrieved memory is appended directly as prior knowledge ([Storage & Retrieval](https://arxiv.org/html/2508.06433v2#S4.SS2)). |
| **Task similarity is the natural index.** | Should “looks like this task” outrank authority, recency, scope, or contradiction status? | First determine eligible memory by epistemic/temporal/ownership rules; rank only inside that set. | Argmax similarity formulation and cosine retrieval ([Eqs. 4–5](https://arxiv.org/html/2508.06433v2#S3.SS1)). |
| **A memory is instruction-shaped.** | Must experience become advice to the future agent? | Store observations as contestable, non-operative claims that cannot guide action until separately authorized. | Memory is defined as reusable templates, procedures, scripts, tool sequences, and recovery tactics ([Introduction](https://arxiv.org/html/2508.06433v2#S1)). |
| **Success makes an experience epistemically good.** | Does accomplishing the task validate the content of the trajectory? | Validate each extracted claim independently; permit useful failures and reject successful-but-unsafe content. | Gold-trajectory offline store and success-only Validation ([Storage & Retrieval](https://arxiv.org/html/2508.06433v2#S4.SS2); [Update](https://arxiv.org/html/2508.06433v2#S4.SS3)). |
| **Failure means the procedure should change.** | When a memory-assisted execution fails, what component was actually wrong? | Maintain causal error labels across retrieval, ranking, interpretation, tool state, policy, and memory before any belief is rewritten. | Adjustment rewrites original memory from a failed execution ([Update](https://arxiv.org/html/2508.06433v2#S4.SS3)). |
| **The current memory is enough; history is optional.** | Should revision erase the epistemic path by which the current item arose? | A bitemporal event log where every derived memory is reproducible and every correction remains contestable. | “Revised in place”; no visible version/provenance model ([Update](https://arxiv.org/html/2508.06433v2#S4.SS3)). |
| **Forgetting is capacity/performance management.** | Is forgetting an optimization operation, a response to staleness, or a person's enforceable right? | Durable “do not re-derive” suppressions that survive source reprocessing, separated from ordinary deletion. | Removal/deprecation is framed as repository maintenance; implementation is underspecified ([Preliminary](https://arxiv.org/html/2508.06433v2#S3)). |
| **More retrieval is good until context interference makes it bad.** | What if the primary cost of a retrieved memory is inappropriate influence, not tokens? | Measure the counterfactual harm of a memory being available to generation even when it is never quoted. | Scaling analysis explains decline through context length and inaccurate memories ([Scaling Retrieval](https://arxiv.org/html/2508.06433v2#S5.SS3)). |
| **A benchmark environment can be the user.** | Who notices, understands, and contests a memory error? | Treat legibility and correction mechanics as part of the memory algorithm, not a UI added after evaluation. | Evaluation ends at environment reward or gold-plan comparison ([Evaluation](https://arxiv.org/html/2508.06433v2#S4.SS1)). |
| **Natural-language artifacts are portable across models.** | What invariants must survive a backbone change besides average reward? | A conformance suite that rechecks memory truthfulness, non-disclosure, abstention, and update behavior per consumer model. | Transfer is established by aggregate completion/step gains ([Transferability](https://arxiv.org/html/2508.06433v2#S5.SS2)). |
| **Silence about uncertainty is acceptable.** | Must a memory say how it came to be believed and how strongly? | Make uncertainty grammar structural: facts, observations, and hypotheses are different executable types. | Stored scripts/trajectories have no reported epistemic tier or calibrated uncertainty field ([Storage & Retrieval](https://arxiv.org/html/2508.06433v2#S4.SS2)). |

## 4. Questions the paper never faced

These arise specifically from Kivi's position and product surface, not from gaps in procedural-memory research in the abstract.

### Admission, subject, and retention

1. **When one interaction contains the user's words, quoted third-party words, and application context, what should determine the subject and retention rights of each candidate memory?** Kivi reads all three but commits to retaining only work-level residue about the user's world.
2. **When useful work facts and forbidden personal facts are entangled in one sentence, should redaction happen before extraction, during candidate construction, or at the storage boundary—and what evidence proves the rejected fragment never crossed the write boundary?**
3. **When a candidate falls into a sensitive category but the user explicitly asks Kivi to remember it, which should govern: the hard exclusion, explicit instruction, or a distinct consent flow?** The position sets a default hard exclusion but does not resolve this collision.
4. **When a statement concerns both the user and another person, what test distinguishes a user-world relation from retained third-party personal content?** “Priya is the client contact” and “Priya is out because her mother is ill” demonstrate the line but not all boundary cases.
5. **What should be retained about the act of dropping a memory candidate without retaining enough content in the drop log to recreate the very privacy violation?**

### Representation and epistemic authority

6. **When the same content can be an entity fact, preference, or episode, what should determine its type and therefore its downstream rights?**
7. **When the user states a belief tentatively, does “stated” describe source authority, certainty, or both?** The Kivi schema separates tier from type but not necessarily source authority from confidence.
8. **When repeated observed behavior contradicts an explicit stated preference, which should control action, which should be visible, and should the contradiction itself become a memory?**
9. **When multiple transcripts jointly support an observation, what evidence threshold and diversity of contexts make it a genuine pattern rather than repeated instances of one situation?**
10. **When a hypothesis is stored grammatically as a question, what technical boundary prevents it from influencing generation as though it were a claim?**
11. **When an inline correction changes an entity fact, how should dependent memories, aliases, relationships, and prior generated artifacts inherit or resist that correction?**

### Retrieval, use, and disclosure

12. **When ordinary dictation contains an explicit interactive request, what determines whether the dictation-only or Hey Kivi memory rights apply?**
13. **When a lexical/entity memory and a higher-tier observation both improve transcription accuracy, should structural path isolation override accuracy?**
14. **When Kivi retrieves a memory it is forbidden to disclose, may that memory silently influence wording, tool choice, ordering, or omission?** The position clearly gates what may be said, but “use” has subtler forms than quotation.
15. **When several relevant memories span different epistemic tiers, should the response be composed from the permitted subset or composed broadly and then redacted?** These paths have different leakage and coherence risks.
16. **When Anbu withholds an observation but displays “Kivi noticed something here,” does revealing the existence of a withheld memory itself exceed the mode's permission?**
17. **When Daari is unlocked by language such as “what do you think?”, what should distinguish a genuine per-request invitation from idiomatic phrasing inside dictation or quoted third-party content?**
18. **When a relevant memory is stale, superseded, suppressed, or low-evidence, should it be excluded before ranking, retrieved for conflict detection, or surfaced as uncertainty?**
19. **When retrieval finds evidence adjacent to—but not answering—the question, what minimum evidence boundary triggers Kivi's specific abstention response rather than a partial answer?**

### Correction, time, and non-regrowth

20. **When the user says “that's not me anymore,” what scope should the suppression cover: exact wording, semantic equivalents, the underlying evidence, a time interval, or a whole category of inference?**
21. **When new behavior later supports a suppressed observation, what should permit reconsideration: time, explicit invitation, qualitatively new evidence, or never?**
22. **When a source transcript is corrected or deleted, which derived memories and evidence counts must change, and how should historical auditability coexist with forgetting?**
23. **When a fact changes naturally rather than being corrected—role change, project rename, new email style—what should distinguish supersession from contradiction and from context-specific variation?**
24. **When an observation decays, should its source evidence remain searchable, should the user still see it in history, and may it contribute to future re-observation?**
25. **When an unconfirmed hypothesis expires, what traces, if any, may remain without becoming a “quiet file of unanswered questions”?**

### User experience and failure cost

## 5. Evaluation gap

### What the paper measured

| Setting | Measures | What the measure can support |
|---|---|---|
| ALFWorld | Binary task reward on dev/test; execution steps until completion or cap | Whether a memory condition changes household-task completion and interaction efficiency in a text environment |
| TravelPlanner | Common-sense score; hard-constraint score after GPT-4o converts the final plan to JSON; execution steps | Whether memory conditions change benchmark-plan quality and interaction length under the benchmark's constraints |
| Build ablation | No memory vs Script vs Trajectory vs Proceduralization across three backbones | Comparative downstream utility of these procedural representations in the tested tasks |
| Retrieval ablation | Random vs Query vs AveFact on TravelPlanner | Comparative downstream utility of the tested keying strategies—not retrieval correctness directly |
| Sequential update | Reward/accuracy and steps across task groups | Whether aggregate performance changes as the tested repository updates accumulate |
| Transfer | Task completion and steps when GPT-4o-created memory is consumed by Qwen2.5-14B | Whether an external natural-language procedural store can improve a weaker model on average |
| Case study | Nine fewer steps and 685 fewer tokens in one illustrated ALFWorld trajectory | A concrete mechanism by which relevant procedural guidance can reduce exploration |

### Decisions the metrics cannot distinguish

Two systems can receive the same reported score while answering these design questions differently:

| Indistinguishable alternatives under the paper's metrics | Why the reported evaluation cannot choose between them | Related decisions |
|---|---|---|
| Store verbatim third-party/private content vs redact it before storage, if both complete the task | No retention, leakage, subject, or consent metric exists. | D1, D2, D18, D19 |
| Retrieve forbidden content but suppress it vs never retrieve it | Only final task success/steps are observed; internal access and influence are unmeasured. | D6, D8, D15 |
| Use a stated fact vs an inferred pattern with identical wording | No epistemic-tier, evidence, or confirmation metric exists. | D5, D10, D14 |
| Preserve provenance/version history vs keep only a rewritten current script | Both can yield the same next-task action and reward. | D9, D14 |
| Correct a memory vs merely route around it for the evaluated task | Evaluation does not probe the belief directly or replay the causal source. | D9, D13 |
| Delete a memory vs suppress its use vs suppress its re-derivation | No reprocessing/regrowth test exists. | D12 |
| Abstain truthfully vs guess correctly | Correct guesses are rewarded; calibrated refusal is not separately scored and may fail completion. | D16, D20 |
| Ask a clarifying question vs perform extra environmental exploration | Both mainly register as additional steps; their safety and information value are not distinguished. | D6, D16 |
| Apply memory in dictation vs reserve it for an explicit assistant request | The benchmarks have no competing surface contracts. | D7, D8 |
| Explain memory use vs provide an opaque but correct output | No user comprehension, trust, contestability, or trace-fidelity measure exists. | D14, D15 |
| Revise after user correction vs after an environment reward | The benchmarks contain no user with privileged authority over semantic facts. | D10, D11 |
| Model a changed preference as supersession vs contradiction vs context-specific exception | Static benchmark scoring observes only whether the immediate task succeeds. | D9, D12 |
| Transfer a memory while preserving privacy/disclosure invariants vs transfer it with changed behavior | Transfer is judged only by aggregate completion and steps. | D17 |
| Retrieve one highly relevant memory vs several mutually redundant memories | If outcome and steps match, retrieval precision, diversity, and context cost below failure threshold are invisible. | D5, D6 |
| Optimize for user control at a small efficiency cost vs optimize steps | The metrics structurally favor fewer steps and do not credit intentional confirmation/correction interactions. | D11, D15, D20 |

### Where the paper supplies evidence versus precedent only

The paper supplies comparative evidence for four narrow propositions in its benchmark setting: representation granularity affects task results; retrieval-key construction affects results; retrieval quantity has a non-monotonic effect; and feedback-driven procedural updating can improve later procedural tasks. Even these findings transfer to Kivi only as hypotheses because Kivi's memory objects and error costs differ.

For admission boundaries, third-party non-retention, epistemic tiers, disclosure permissions, provenance, abstention, corrections, suppression, decay, user-visible inspection, and memory rights by product surface, the paper supplies **precedent only or no precedent at all**. Its metrics cannot show whether those decisions are correct, safe, legible, or durable for Kivi.

## Underspecified items that should not be inferred from the paper

- The exact prompts used to build scripts, extract AveFact keywords, and revise memory after failure.
- Whether “Script” is one global manual, one script per trajectory, or another grouping.
- The embedding model, index implementation, similarity thresholds, tie-breaking, and exact top-k values in the HTML text.
- The refresh interval *t* and sensitivity to batch size.
- The implemented mechanism for deletion, deprecation, or dynamic discarding claimed in the abstract/framework.
- The exact “reflection” mechanism: the strategy list calls it Adjustment, while the results discussion calls a reflexion-based mechanism strongest.
- How an erroneous retrieved memory is causally identified as the reason for failure.
- Whether adjusted memories retain their original text, sources, versions, or rollback path.
- How duplicate, contradictory, or near-identical memories are detected and reconciled.
- Repository scale, storage cost, build/update latency, and end-to-end latency overhead.
- Any security, prompt-injection, tenant-isolation, privacy, consent, or deletion behavior.
- Any abstention, confidence, clarification, or user-facing explanation policy.
