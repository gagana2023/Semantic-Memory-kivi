# TraceMem inverted: the design questions it answers

**Paper:** Yiming Shu et al., *TraceMem: Weaving Narrative Memory Schemata from User Conversational Traces* (arXiv:2602.09712v1, 10 February 2026)  
**Target setting:** Kivi, as specified in *The Things Kivi Comes to Know*  
**Reading note:** Section and page references point to the paper PDF. “Underspecified” means the paper does not commit clearly enough to infer an implementation safely. This document maps choices; it does not recommend answers.

## 1. Decision inventory

| ID | Decision question | TraceMem's answer | Defensible alternatives | Assumptions behind that answer | Does it hold for Kivi? | Paper location |
|---|---|---|---|---|---|---|
| D1 ★ | When conversational history enters memory, should the basic retained object be raw turns, fixed chunks, topic-bounded episodes, extracted facts, or some combination? | Retain topic-bounded episode summaries plus exhaustive transient semantics, then derive user experience traces. | Raw turns; fixed token chunks; event-boundaries based on action/time; structured facts only; user-authored saves only. | Long, multi-session dialogues; topic coherence is a useful compression boundary; offline storage can afford multiple representations; loss of wording is tolerable. | **Partly.** Kivi has transcripts plus application context and two product paths. | D2 ★ | When should a new episode begin: at every session boundary, at fixed size, or when a model infers a topic change using surrounding context? | Classify every utterance as topic change or topic development using preceding **and subsequent** context; contiguous same-topic utterances form an episode. | Online one-sided segmentation; fixed windows; speaker-turn boundaries; explicit user markers; temporal/event segmentation; overlapping episodes. | Subsequent context exists before final segmentation; reprocessing delay is acceptable; topics are mostly contiguous; the binary TC/TD distinction is sufficient. | **Partly.** Kivi leaves extraction timing open and may process live dictation. | D4 ★ | When dialogue concerns several people, whose experience should be converted into durable personal memory? | Build a separate trace/card for each participant; facts about another person are retained in that person’s own trace, even if mentioned during someone else’s topic. | Persist only the product’s primary user; retain work-level relational residue only; require each subject’s consent; keep third-party content transient. | All dialogue participants are legitimate memory subjects; the benchmark treats reciprocal knowledge as desirable; consent and asymmetric ownership are outside scope. | **No.** Kivi has a hard non-retention rule for others. The difference pushes away from symmetric participant cards and toward a user-scoped write barrier with only non-characterizing work relations surviving. | [§3.2, pp. 4](https://arxiv.org/pdf/2602.09712#page=4); Appendix A, “User Experience Traces Distillation,” p. 11; Table 3 counts traces for both users, p. 6. |
| D5 ★ | Which candidate facts deserve durable retention: all personal experiences, only concrete biographical facts, only user-confirmed facts, or only task-relevant durable facts? | A prompt rule retains concrete biographical facts and contextual details about the subject’s own life; acknowledgements and social pleasantries are filtered. | Explicit saves only; durable work facts only; utility-weighted memories; schema categories with exclusions; sampled/expiring episodes. | A broad life narrative is the product goal; “own-life concrete fact” is an adequate safety and relevance boundary; model-based prompt filtering is sufficient. | **No.** Kivi’s test is re-explanation cost plus work-level scope, with hard exclusions. The difference pushes toward narrower eligibility and enforcement outside a prompt. | [§3.2, pp. 4](https://arxiv.org/pdf/2602.09712#page=4); Appendix A, “Persona Slice Extraction,” p. 11. |
| D6 | When information is filtered out, should the system delete it silently, preserve it as an episode, log the rejection, or expose the reason? | Trace distillation can return `N/A`; episode summaries remain. The paper reports aggregate “discard rate,” but per-item reason logging and user exposure are **underspecified**. | Destructive drop; reason-coded audit log; user-visible “read, not kept”; quarantine for review; retain only provenance hashes. | Aggregate retention efficiency matters more than proof of a boundary; discarded personal traces need not be auditable to the user. | **No.** Kivi’s trust claim requires candidate-level drop reasons and visible “read, not kept” state. The difference pushes toward explicit write-path telemetry and inspection. | [Table 3 and surrounding text, pp. 6–7](https://arxiv.org/pdf/2602.09712#page=6); Appendix A trace output, p. 11. |
| D7 ★ | Should a memory distinguish what the user stated from what the system observed or hypothesized? | No explicit epistemic tier is stored. Concrete experiences are distilled and summarized into narrative threads; the schema carries hierarchy, summaries, and IDs, not stated/observed/hypothesized status. | Provenance tiers; confidence distributions; claim/evidence graphs; hypotheses stored only as questions; no inferred persona layer. | Narrative coherence can stand in for epistemic qualification; inferred summaries are safe to use like retrieved facts; benchmark answers reward content match, not epistemic discipline. | **No.** Kivi’s product hinges on the distinction. The difference pushes toward tier-bearing claims, evidence counts, and explicit confirmation events rather than a flat narrative schema. | [§3.2–3.3.2, pp. 4–5](https://arxiv.org/pdf/2602.09712#page=4); Fig. 3, p. 4. |
| D8 ★ | When many traces accumulate, should organization be chronological, graph-based, schema-based, or discovered through semantic clustering? | Use PCA → UMAP → HDBSCAN; reassign all noise with KNN; cluster first into topics and then into fine-grained, chronologically sequential threads. | Temporal index; entity/relation graph; fixed ontology; hybrid symbolic/vector index; leave low-density items unclustered; multiple memberships. | Enough traces exist to form density structure; embeddings encode useful personal similarity; every outlier belongs somewhere; global re-clustering cost is acceptable. | **Partly/unknown.** Kivi’s initial corpus is small and deliberately typed. Small per-user data weakens density assumptions; forced reassignment raises the cost of false coherence. Scale, latency, and cost targets are explicitly undecided in Kivi. | [§3.3.1, Eqs. 4–5, pp. 4–5](https://arxiv.org/pdf/2602.09712#page=4); §4.1.4, p. 6. |
| D9 | When a trace is an outlier, should it remain noise, be discarded, or be forced into the nearest narrative? | HDBSCAN flags noise; KNN then assigns every noise point to the nearest coherent cluster. | Preserve an unclustered bucket; discard; create singleton threads; ask for confirmation; allow multi-membership. | Completeness and navigability outweigh the risk of a wrong association; nearest-cluster distance is meaningful after nonlinear reduction. | **Probably no.** Kivi makes false characterization and sticky inference high-cost. The difference pushes toward visible uncertainty or non-membership rather than mandatory narrative placement. | [§3.3.1, p. 4](https://arxiv.org/pdf/2602.09712#page=4). |
| D10 ★ | What should the long-term user model expose to retrieval: atomic claims, a graph, chronological episodes, or a summarized narrative hierarchy? | A three-level memory card: overall theme → topic → thread title/summary/ID, with thread content separately retrievable. | Flat fact store; entity graph; timeline; user-curated collections; tiered claim/evidence cards. | A coherent persona/life story is useful; summary abstraction does not create unacceptable characterization; users do not need to edit the schema directly. | **No in its current form.** Kivi explicitly rejects a psychological profile and groups memory by epistemic tier. The difference pushes away from “overall narrative arc” and toward claim-level, source-attributable, reversible records. | [§3.3.2 and Fig. 3, pp. 4–5](https://arxiv.org/pdf/2602.09712#page=4). |
| D11 ★ | At query time, should retrieval use one index or combine direct episodic similarity with navigation through a user-level schema? | In parallel, retrieve top-10 episodic memories by vector similarity and use an LLM to select card(s) and up to 10 threads per person; fuse both for answering. | Episodic only; card/thread only; hybrid lexical/vector/structured query; query decomposition; reranking; retrieve all then gate; surface-specific retrievers. | Extra model calls and latency are acceptable; questions identify people/topics; redundancy improves reasoning; global episodic search is safe. | **Partly.** Hybrid retrieval may fit Hey Kivi, but Kivi requires a separate lexical/entity-only path for dictation. The paper’s one query pipeline does not encode different memory rights. | [§3.4 and Fig. 4, p. 5](https://arxiv.org/pdf/2602.09712#page=5); §4.1.4, p. 6; Appendix A, pp. 12–13. |
| D12 | What should select the relevant person-level memory: explicit identity, query cues inferred by a model, authorization scope, or all available cards? | An LLM chooses one or both user cards from query cues; it must select at least one. | Authenticated subject scope; deterministic entity resolution; search all cards; no persona cards; abstain if subject unclear. | There are exactly two known interlocutors; one or both must be relevant; identity ambiguity and access control are absent. | **No.** Kivi has one primary memory subject and transient third-party context. The difference pushes from open card selection to an authorization boundary fixed before retrieval. | [§3.4, p. 5](https://arxiv.org/pdf/2602.09712#page=5); Appendix A, “User Card Choice,” p. 12. |
| D13 ★ | When memory exists but the interaction contract does not call for it, should the system still retrieve it, suppress retrieval, or retrieve and gate disclosure? | Implemented system retrieves for answering; when not to invoke memory is deferred as future work. No disclosure policy is specified. | Never retrieve in restricted surfaces; retrieve all then permission-gate disclosure; query-level opt-in; intent-based activation; user-set modes. | Benchmark questions always request memory; user discomfort, surprise, and information hazards are not measured; more relevant context generally helps. | **No.** Kivi separates retrieval from disclosure for Hey Kivi and structurally prevents observation/hypothesis retrieval in dictation. The difference creates two decisions TraceMem never operationalizes. | [§3.4, p. 5](https://arxiv.org/pdf/2602.09712#page=5); §5, pp. 7–8. |
| D14 ★ | When retrieved evidence is missing, ambiguous, or contradictory, should the system abstain, ask, expose uncertainty, or guess? | The answer prompt says that if evidence is unavailable, “try your best guess.” Conflict resolution is **underspecified**. | Calibrated abstention; clarification; evidence-ranked answer; present conflicting versions; refuse unsupported claims. | Every benchmark question has a gold answer; answer completion is rewarded; plausible error has low modeled cost; user can tolerate unverifiable fluency. | **No.** Kivi explicitly forbids filling gaps and makes actionable abstention a trust surface. The difference pushes toward retrieval traces, absence claims, and no-answer evaluation. | Appendix A, “Answer Prompt Template,” rule 6, p. 12; evaluation scheme §4.1.3, p. 6. |
| D15 ★ | When newer information conflicts with an older memory, should both remain, should one supersede the other, or should the system reconcile them into a revised claim? | **Underspecified.** Chronological threads retain sequences, but there is no operational contradiction, supersession, correction, or version policy. | Last-write-wins; temporal validity intervals; contradiction graph; user-confirmed supersession; retain both with conflict flag. | Temporal QA can be answered from narrative chronology without maintaining claim validity; there is no user correction workflow. | **No.** Kivi requires supersession history, demotion, suppression, and corrections that survive reprocessing. The difference pushes toward explicit lifecycle state rather than chronology alone. | [§3.3.1, pp. 4–5](https://arxiv.org/pdf/2602.09712#page=4); absence across §3; §5 calls rewriting future work. |
| D16 ★ | What should change over time: cluster organization, claim validity, confidence, retention, or all of them? | The paper calls cards “self-evolving,” apparently through consolidation/reorganization; retrieval-triggered rewriting, decay, and regulated forgetting are only proposed future directions. Update schedule and incremental mechanics are **underspecified**. | Append-only memory; event-driven incremental updates; periodic full reclustering; evidence decay; user-driven revision; expiration by tier. | The benchmark is a completed history rather than a live lifecycle; storage growth and stale persona harm are not evaluated. | **No/unknown.** Kivi requires observation decay, hypothesis expiry, contradiction supersession, and durable suppression. The difference pushes from organizational evolution to explicit epistemic lifecycle mechanics. | [Introduction, pp. 2–3](https://arxiv.org/pdf/2602.09712#page=2); §5, pp. 7–8. |
| D17 | What provenance should survive compression, and who should be able to inspect it? | Thread IDs link card summaries back to thread contents; episodic memories and threads feed the answer. Claim-to-source granularity and a user-facing provenance interface are **underspecified**. | Per-claim transcript IDs; quote spans; evidence counts; immutable lineage graph; no provenance. | Source attribution mainly serves model reasoning and answer accuracy, not user correction or audit. | **Partly.** Kivi also needs source tracing, but at memory-entry level and in a normal-user Why panel. The difference pushes toward explicit claim/evidence lineage and disclosure of used/withheld items. | [§3.3.2–3.4, p. 5](https://arxiv.org/pdf/2602.09712#page=5); Fig. 1 and contributions, pp. 1–3. |
| D18 | What happens when the memory system is wrong: automatic rewrite, silent persistence, user correction, rollback, or deletion? | **Underspecified.** No correction, edit, removal, appeal, or rollback surface is described; rewriting on retrieval is future speculation. | Inline correction; source edit propagation; versioned rollback; user-visible delete/suppress; automatic conflict repair. | Evaluation observes generated answers, not ongoing relationship damage; the benchmark user does not manage memory. | **No.** Kivi treats reversibility as a first principle and requires Confirm, Correct, “That’s not me anymore,” and Forget. The difference pushes toward product and storage operations absent from TraceMem. | Absence across §3–4; [§5, pp. 7–8](https://arxiv.org/pdf/2602.09712#page=7). |
| D19 | Should generation receive all retrieved content, a reranked subset, or a permission-filtered trace with reasons? | Fuse top episodic memories and selected thread contents into the answering context. Reranking, token budgeting, deduplication, and conflict ordering are **underspecified**. | Cross-encoder rerank; maximal marginal relevance; temporal/entity filters; evidence graph traversal; permission gating; citation-first answer context. | Top-k plus schema navigation fits the context budget; duplicate representations are beneficial or harmless; evidence order is not safety-critical. | **Partly/unknown.** Kivi’s Why panel needs to distinguish retrieved, withheld, and used. The difference pushes toward maintaining selection state through generation rather than only a fused context. | [§3.4, p. 5](https://arxiv.org/pdf/2602.09712#page=5); Appendix A, “Agentic Search,” p. 13. |
| D20 | What should the user see of memory operation: only the final answer, citations, the retrieved memories, withheld memories, or the whole editable model? | The paper specifies answer generation, not a user-facing memory or explanation surface; exposure is **underspecified**. | Final answer only; inline citations; expandable retrieval trace; editable memory cards; per-answer permission report. | QA output is the product surface; inspectability and control are outside evaluation. | **No.** Kivi makes the memory surface and Why panel core product surfaces. The difference pushes toward legible tier/provenance/lifecycle UI that the paper provides no evidence about. | Appendix A, “Answer Prompt Template,” p. 12; absence across §3–4. |

## 2. Forced choices

These are the choices for which changing the answer would materially alter either TraceMem’s reported results or the validity of importing it into Kivi.

| IDs | Why the choice is load-bearing | Evidence in the paper |
|---|---|---|
| D1–D2 | Topic-bounded episodic memory is the substrate for every later summary and trace. Changing the boundary changes all downstream units. | The complete pipeline begins with deductive episode segmentation (§3.1); “Episodic Memory Only” still scores 0.8429 overall (Table 4). |
| D3–D5 | Exhaustive extraction and broad own-life trace retention determine what information remains available for both episodic and narrative retrieval. Narrow privacy gates would change benchmark recall and the card content. | Extraction and persona-slice prompts require exhaustive details (Appendix A, pp. 10–11); discard rates vary materially by backbone (Table 3). |
| D7–D10 | The central contribution is conversion of traces into persona-like narrative schemata. Removing or epistemically qualifying that abstraction would change the system being evaluated. | §3.3 and Fig. 3 define the schema; the abstract and contribution claims center on coherent narratives and persona. |
| D11 | Dual episodic + card/thread retrieval materially affects results. | Removing agentic search lowers overall accuracy from 0.9019 to 0.8844 and multi-hop from 0.9220 to 0.8652 (Table 4). |
| D13–D14 | Always answering memory questions and guessing under missing evidence define the response behavior. An abstaining system can score worse despite being safer, so the reported accuracy cannot transfer directly to Kivi. | Answer prompt rule 6; binary correctness evaluation (§4.1.3 and Appendix A). |
| D15–D16 | TraceMem’s claimed evolving narrative has no operational validity/correction lifecycle. Adding supersession, decay, or suppression can remove evidence the benchmark expects and change temporal answers. | §5 explicitly leaves rewriting and forgetting for future work. |

## 3. Unexamined defaults

| Default the paper inherits | The choice hiding inside it | Alternative this line of work rarely tests |
|---|---|---|
| Memory quality means answer accuracy. | A memory system is good when it helps reproduce a gold fact, irrespective of whether retaining or saying that fact was appropriate. | Evaluate *appropriate non-retention*, *appropriate non-disclosure*, and *useful abstention* alongside recall. |
| Every benchmark participant is a legitimate persona target. | Reciprocal conversational access implies permission to build durable models of each person. | Give one participant memory rights and treat everyone else as transient context. |
| More exhaustive extraction is safer for recall. | Omission is treated as the dominant failure; invasive retention is not scored as failure. | Score the system on facts it correctly refuses to store, including sensitive and third-party facts. |
| A coherent narrative is preferable to fragmented claims. | Coherence is assumed to reveal structure rather than manufacture it. | Preserve plural, conflicting, or unclustered claims without forcing a unifying persona story. |
| Every outlier belongs to a nearest cluster. | HDBSCAN noise is an engineering inconvenience rather than meaningful uncertainty. | Maintain “unplaced” memory as a first-class state and measure whether later evidence resolves it. |
| Summaries are neutral compression. | Summarization is treated as content-preserving, although it can introduce interpretation, causal framing, and characterisation. | Store claim/evidence units and generate temporary narratives at query time, never durable summaries. |
| One retrieval policy fits every conversational act. | If a query can benefit from memory, retrieval is presumed allowed. | Give transcription, drafting, recall, and reflection distinct hardware/schema-level memory rights. |
| Retrieval success justifies disclosure. | The system does not distinguish “known,” “relevant,” and “permitted to say.” | Retrieve broadly for inspection while applying an independently testable disclosure policy. |
| Silence about uncertainty permits a guess. | Completion is valued over calibrated absence. | Treat an evidence-backed negative result as a successful answer and expose the search scope. |
| Time is primarily sequence. | Temporal ordering is used for reasoning, not for validity, decay, or identity change. | Model “true during,” “superseded by,” “no longer me,” and “must not be re-derived” as separate state transitions. |
| Source attribution is for the reasoning engine. | IDs make content retrievable, but do not automatically make beliefs contestable to a person. | Make every user-visible belief open to its exact source span and a reversible action. |
| A completed dialogue is an adequate proxy for a living system. | Construction is evaluated after a static corpus, avoiding concurrent writes, reprocessing, correction, and drift. | Evaluate a longitudinal loop in which users correct memory and old source data is replayed. |

## 4. Questions the paper never faced

These come from Kivi’s stated users, surfaces, constraints, and failure costs—not from gaps inferred generically from TraceMem.

1. When application context contains another person’s private information needed for a reply, what exact transformation may survive as work-level residue without becoming a memory *about that person*?
2. When the same input supports both an allowed work fact and an excluded sensitive inference, where must the enforcement boundary sit so the latter cannot reach storage, embeddings, logs, or summaries?
3. When regular dictation and Hey Kivi consume the same transcript history, what should make it impossible—not merely unlikely—for observations or hypotheses to enter the dictation path?
4. When all tiers are retrieved for Hey Kivi, what state must be recorded to prove that an observation was withheld under Anbu rather than simply missed by retrieval?
5. When a user taps “Kivi noticed something here,” should this one-time disclosure alter the persistent permission mode, the memory’s tier, neither, or both?
6. When an observed pattern has many examples but no explicit confirmation, what evidence count, temporal spread, and counterexample policy determine whether it may be surfaced as an observation?
7. When a user says “that’s not me anymore,” what should be suppressed: one rendered sentence, an underlying pattern signature, all supporting evidence, or future derivations within a semantic neighborhood?
8. When “Forget” and provenance/audit requirements conflict, which artifacts—source transcript, derived claim, rejection log, suppression key—remain, and who can inspect them?
9. When a correction arrives inline during a task, what should happen to the current answer, old source-attributed memory, dependent observations, and reprocessing of the original transcript?
10. When a stated fact and a newer observed pattern disagree, which tier controls action, which may be disclosed, and how should the contradiction appear in the Why panel?
11. When a hypothesis is invited for one Daari response, what prevents its generated rationale, retrieval trail, or model cache from becoming a durable belief?
12. When confirmation prompts are rationed, what makes one uncertainty higher-value than another without constructing the kind of psychological utility model Kivi rejects?
13. When an excluded candidate is logged to prove the boundary, how much content can the log contain before the log itself becomes forbidden retention?
14. When an entity fact concerns both the user’s work and a third party—“Priya is the Acme contact”—what ownership and expiry rules distinguish acceptable relational residue from a shadow profile?
15. When a memory is correct but socially inappropriate to mention, how should Kivi distinguish retrieval quality, disclosure-policy quality, and final-answer quality in its trace and evaluation?
16. When a user changes mode or revokes permission, does that affect only future disclosure, previously generated outputs, cached contexts, or stored hypotheses as well?
17. When there is genuinely no answer, what evidence must an abstention display to be useful without leaking withheld or third-party content?
18. When a memory entry is edited by the user, is the edited content a stated fact, a correction event linked to the old claim, or both—and what should downstream re-clustering be allowed to rewrite?

## 5. Evaluation gap

### What TraceMem measured

- **Dataset:** LoCoMo: 10 long dialogues, about 600 turns each, and 1,540 questions (§4.1.1).
- **Task categories:** single-hop, multi-hop, temporal, and open-domain QA (§4.1.1).
- **Outcome:** semantic-match accuracy against a gold answer, judged CORRECT/WRONG by GPT-4o-mini (§4.1.3; Appendix A).
- **Comparisons:** FullText, NaiveRAG, A-Mem, LightMem, and Nemori (Table 2).
- **Ablations:** episodic-only; episodic plus 20 or 40 semantic representations; no agentic search; full system (Table 4).
- **Process counts:** numbers of episodes, experience traces, threads, and a derived aggregate discard rate (Table 3).

### What those metrics can and cannot distinguish

| Decision(s) | Distinguishable under the paper’s evaluation? | Why |
|---|---|---|
| D1–D2: memory unit and segmentation | **Partly.** | Episodic-only and downstream ablations show the chosen representation can support QA, but no controlled comparison isolates bidirectional topic segmentation from fixed, event, or online segmentation. |
| D3–D6: exhaustive extraction, retention scope, third-party policy, discard logging | **Mostly no.** | If two systems preserve the gold answer, one may retain every sensitive detail and the other may minimize aggressively; both score identically. Aggregate discard rate has no correctness or safety labels. |
| D7: epistemic tiers | **No.** | A stated fact and a model-inferred characterization receive the same credit if the final text touches the gold topic. The metric does not test confirmation or appropriate hedging. |
| D8–D10: clustering, outlier assignment, narrative hierarchy | **Partly.** | Full-system gains over weaker memory formulations support the bundle, but there is no ablation for PCA, UMAP, HDBSCAN, KNN reassignment, number of hierarchy levels, or narrative summaries versus claim graphs. Many alternative organizations could produce the same answers. |
| D11–D12: dual retrieval and card choice | **Partly.** | “Without Agentic Search” supports the bundled search mechanism for multi-hop accuracy. It does not distinguish LLM card selection from deterministic subject scoping, alternative rerankers, or different top-k values. |
| D13: when to invoke/retrieve/disclose | **No.** | Every benchmark item is a memory question. There are no tasks where memory is irrelevant, disallowed, socially inappropriate, or should be withheld. |
| D14: abstain versus guess | **No—and the metric pushes the opposite way.** | Binary gold-answer accuracy rewards a lucky guess and cannot credit an honest, useful abstention unless abstention happens to match the gold answer. No unanswerable questions are described. |
| D15–D16: contradiction, supersession, decay, forgetting | **Mostly no.** | Temporal questions test sequence recall, not live claim validity, user correction, decay, replay after suppression, or stale identity harm. |
| D17–D20: provenance, error recovery, context selection, user exposure | **No.** | The judge sees only question, gold answer, and generated answer. Two systems with identical outputs but radically different sources, withheld items, user controls, or correction paths receive the same score. |

### The central transfer limit

TraceMem provides evidence that its **representation-and-retrieval bundle** is effective at recovering benchmark facts, especially across multiple turns and time. It provides only precedent—not evidence—for Kivi’s decisions about what may be retained, whose information may persist, whether an inference is allowed to act like a fact, when a retrieved memory may be disclosed, how to abstain, how corrections persist, and how the user inspects or reverses the model.

The sharpest mismatch is this: TraceMem’s evaluator rewards the presence of the right answer; Kivi’s contract also requires evidence that some available information was deliberately **not stored, not retrieved, not disclosed, or not guessed**. Those outcomes are invisible to the paper’s metric.
