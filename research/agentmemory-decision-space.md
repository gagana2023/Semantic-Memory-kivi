# AgentMemory Decision Space for Kivi

## Scope and evidence standard

This report examines AgentMemory commit `e04ba88819c365c9acf9d6661ea802143e728bd6` and compares it with Kivi's position paper. A statement marked **inference** is derived from behavior rather than stated intent. “Unclear” means neither code, comment, blame, changelog, issue, nor test supplied a reason. Code references use repository-relative `file:line`; Kivi references use `../kivi-semantic-memory-position.md:line`.

The analysis read the complete Kivi position paper; `AGENTS.md`; `package.json`; the type and namespace definitions; startup/configuration; capture, privacy, compression, explicit-memory, consolidation, retention, retrieval, ranking, graph-retrieval, audit, and persistence paths; relevant test titles and the test bodies for the decisions cited below; `CHANGELOG.md`; 482 local commits; selected blame ranges; and linked public issues/PRs named by the changelog. It skipped translated READMEs, visual assets, website/viewer presentation code, deployment recipes except where persistence history depended on them, benchmark payloads, and most connector-installation code. The default suite was not run because dependencies were not installed; its command excludes the integration test (`package.json:24-27`). There are 161 `*.test.ts` files and approximately 1,718 `it`/`test` declarations by static count; that count is not a test result.

## Orientation

### Logic versus glue

The substantive memory behavior lives in `src/functions/` and the retrieval/index machinery in `src/state/`; `src/index.ts` instantiates providers, storage and indexes and registers each behavior (`src/index.ts:157-253`, `src/index.ts:270-401`). `src/triggers/`, `src/mcp/`, and `src/hooks/` translate durable events, REST, MCP, and agent lifecycle signals into those functions (`src/triggers/events.ts:43-169`). `src/cli/`, `integrations/`, `examples/`, `deploy/`, `viewer/`, `benchmark/`, and `eval/` are adapters, operations, presentation, or evaluation rather than the core semantics; this classification is an inference from dependency direction and registration structure (`src/index.ts:28-105`, `package.json:16-32`).

### Data model

The ingestion model is a `Session` containing `RawObservation` and derived `CompressedObservation` records; raw observations can preserve tool input/output, prompts, and arbitrary raw payloads (`src/types.ts:1-15`, `src/types.ts:47-82`). Long-lived `Memory` is a separate versioned record with one of six domain types, strength, sources, optional TTL, project/agent scope, and latest-version marker (`src/types.ts:102-125`). A second consolidation family stores `SemanticMemory` and `ProceduralMemory`, which is semantically distinct from `Memory` and has different provenance and lifecycle fields (`src/types.ts:515-548`). Graph, audit, access, retention, lesson, slot, action, and other records occupy independent KV namespaces (`src/state/schema.ts:4-75`).

The storage API is schemaless KV over iii-engine's `state::get/set/update/delete/list` operations (`src/state/kv.ts:3-46`); iii-engine persists that state in file-backed SQLite (`AGENTS.md:5-9`). IDs are either time/random UUID fragments or truncated SHA-256 fingerprints (`src/state/schema.ts:84-93`). Export/import is versioned and capped, making JSON the portability boundary (`src/types.ts:323-355`, `src/functions/export-import.ts:227-294`).

### Main execution path

An agent hook or API produces an observation event; the durable subscriber forwards it to `mem::observe` (`src/triggers/events.ts:87-94`). Capture validates only session/hook/timestamp, strips explicit private tags and recognized secret patterns, classifies provenance by hook type, then stores a raw observation under a per-session scope (`src/functions/observe.ts:49-114`, `src/functions/observe.ts:146-198`). The default path derives a synthetic compressed observation; an opt-in path invokes an LLM compressor (`src/functions/observe.ts:302-358`). Search indexes the compressed representation; explicit `mem::remember` calls separately create a durable `Memory`, detect similar existing memories, version/supersede one, persist it, and update indexes (`src/functions/remember.ts:71-220`).

Recall enters `mem::search` or `mem::smart-search`. The primary path defaults to 20 results, caps at 100, over-fetches when scoping filters apply, and uses hybrid ranking when vectors exist, otherwise BM25 (`src/functions/search.ts:369-504`). Hybrid search fetches twice the requested depth from BM25 and vector streams, optionally adds graph results, fuses ranks with weighted reciprocal-rank fusion, diversifies by session, enriches stored rows, optionally reranks the first 20, and truncates (`src/state/hybrid-search.ts:81-258`). Session stop summarizes and may asynchronously run graph extraction, consolidation, and crystallization, globally debounced by a cooldown marker (`src/triggers/events.ts:96-147`).

### Configuration surface

Configuration is not one schema. It is distributed across `src/config.ts`, direct `process.env` reads in feature modules, `.env.example`, iii YAML, and request parameters. Process environment wins over `~/.agentmemory/.env`, which is memoized for process lifetime (`src/config.ts:25-59`, `src/config.ts:74-83`, `src/config.ts:223-231`). The settings found on the memory execution path are catalogued in “Magic numbers”; notable Boolean gates are LLM compression, context injection, consolidation, graph extraction, snapshots, slots/reflection, stale-index dropping, image embeddings, agent isolation, team sharing, standalone MCP, and provider fallback (`src/config.ts:234-235`, `src/config.ts:284-308`, `src/config.ts:311-339`, `src/config.ts:359-381`, `src/config.ts:402-471`, `src/functions/observe.ts:183-193`).

### What tests exercise

The tests strongly exercise function-local validation and transformations against mocked SDK/KV: capture/dedup/compression, supersession, search/index fusion, project and agent isolation, retention, privacy regexes, consolidation gates, provider failures, hooks, and API/MCP shape. Regression tests explicitly distinguish the new defaults for auto-compression and context injection (`test/auto-compress.test.ts:75-149`, `test/context-injection.test.ts:57-114`), cross-agent search behavior (`test/agent-isolation-search.test.ts:133-190`), project-scoped consolidation (`test/consolidate-project-scope.test.ts:119-248`), and retention of both episodic and semantic rows (`test/retention.test.ts:436-490`). The suite does not, by default, exercise the real engine boundary because `test/integration.test.ts` is excluded (`package.json:24-27`); most tests mock `iii-sdk`, as the repository itself prescribes (`AGENTS.md:76-80`).

## 1. Decision inventory

| Question with multiple defensible answers | Repository answer and placement | Assumptions frozen into it | Fit to Kivi / direction of difference |
|---|---|---|---|
| What events may enter memory: only user statements, selected application events, or the whole agent/tool lifecycle? | Session, prompt, tool, error, notification, subagent and task hooks can become raw observations (`src/types.ts:139-160`); capture accepts arbitrary `payload.data` after minimal envelope validation (`src/functions/observe.ts:49-99`). This is **hardcoded at the capture architecture**, with connector-specific coverage. | Coding-agent tool exhaust is valuable; third-party material inside tool I/O is acceptable to retain after secret redaction; storage volume is bounded by a session cap. | Does not hold for Kivi. Kivi requires a structural split where third-party content can enter generation context but not the write path (`../kivi-semantic-memory-position.md:106-126`). Difference pushes toward a narrower, actor-aware write contract—not merely more filters. |
| Should privacy mean secret-pattern redaction, subject/category exclusion, or consent-aware routing? | Redacts `<private>` spans and credential-shaped regex matches, then stores everything else (`src/functions/privacy.ts:3-28`; `src/functions/observe.ts:92-114`). **Hardcoded**, suggesting confidence in syntax-level secrecy rather than semantic exclusion. | Sensitive data is recognizable by delimiters/token formats; personal facts are not treated as a special class. | Opposite of Kivi's hard exclusion of health, mood, family, faith, politics, personal finance and character judgments, with logged drop reasons (`../kivi-semantic-memory-position.md:39-50`). Difference pushes from string sanitation to candidate-level semantic policy and audit. |
| Should raw source material survive, or only extracted claims plus provenance pointers? | Stores sanitized arbitrary `raw`, tool input/output, and user prompts in `RawObservation` (`src/types.ts:47-62`; `src/functions/observe.ts:104-130`). **Hardcoded data model**. | Local storage is trusted; forensic replay outweighs minimization; source payload size and third-party rights are secondary. | Kivi wants attributable claims but explicitly refuses to retain third-party personal source content (`../kivi-semantic-memory-position.md:106-126`). Difference pushes toward split storage/access domains or non-retained evidence descriptors. |
| What representation is primary: events, typed claims, entity graph, or epistemic assertions? | Maintains overlapping raw/compressed observations, six-type `Memory`, semantic/procedural stores, graph nodes/edges, lessons and slots (`src/types.ts:47-125`, `src/types.ts:387-548`, `src/state/schema.ts:41-70`). **Pluggable features over a hardcoded multi-store taxonomy**. | Coding work benefits from multiple purpose-specific projections; duplication and divergent lifecycles are manageable. | Kivi specifies orthogonal `type` (entity/preference/episode) and `tier` (stated/observed/hypothesised) on every memory (`../kivi-semantic-memory-position.md:66-104`). Repo precedent does not model epistemic tier; difference pushes toward a single assertion model with explicit projections. |
| Is provenance a mutable annotation or immutable trust-boundary fact? | `Origin` records channel/detail/capture time and is described as immutable write-time provenance; derived records may carry source IDs (`src/types.ts:30-45`, `src/types.ts:117-124`). **Hardcoded field, optional for compatibility**. | Channel is a useful proxy for trust; optionality is acceptable for old data. | Partially holds. Kivi needs actual transcript-level evidence, counts, and confirmation events visible to the person (`../kivi-semantic-memory-position.md:89-103`, `../kivi-semantic-memory-position.md:232-250`). Difference pushes toward required, plural provenance and event history. |
| When are two inputs duplicates: same delivery, same wording, or same proposition? | Hook delivery dedup hashes session + tool name + input for five minutes (`src/functions/dedup.ts:3-16`; `src/functions/observe.ts:66-89`). Durable memory treats Jaccard similarity >0.7 as supersession and >0.4 as an advisory near match (`src/functions/remember.ts:111-140`). **Hardcoded thresholds; algorithm not pluggable**. | Duplicate deliveries recur quickly; lexical overlap approximates semantic identity; one closest high-overlap row is enough. | Weak fit. Kivi distinguishes corroborating evidence, repetition, contradiction, and explicit correction; repeated observations should increase evidence without self-promoting (`../kivi-semantic-memory-position.md:87-101`). Difference pushes toward proposition/entity/time identity and evidence accumulation rather than delivery/content collapse. |
| What happens on conflict: preserve both, merge, reject, or supersede? | The first latest memory above lexical threshold is marked not-latest, retained in KV, removed from recall indexes, and linked as parent/superseded (`src/functions/remember.ts:125-190`). Cascade invalidation runs asynchronously (`src/functions/remember.ts:213-220`). **Hardcoded behavior**. | High lexical overlap means replacement even without contradiction detection; hiding old truth is safer than returning it; eventual cascade is sufficient. | Partially aligns with Kivi's auditable supersession (`../kivi-semantic-memory-position.md:239-244`) but not with its required correction/suppression semantics. Difference pushes toward explicit contradiction type, valid-time, and user-confirmation events. |
| May deleted/corrected beliefs regrow from old evidence? | Forget deletes the selected record/session and index entries; no suppression/tombstone is part of `Memory` (`src/types.ts:102-125`; `src/functions/remember.ts:246-317`). **Hardcoded omission / incomplete for Kivi**. | Re-extraction from retained source is rare or acceptable; delete means row deletion. | Does not hold. Kivi explicitly requires “not me anymore” and “forget” to suppress re-derivation (`../kivi-semantic-memory-position.md:239-247`). Difference pushes toward durable negative constraints keyed to proposition/evidence. |
| Can observed patterns become facts automatically, or only after confirmation? | Consolidation automatically synthesizes semantic/procedural memories when corpus thresholds are met; semantic confidence is supplied by the model and existing confidence takes the maximum (`src/functions/consolidation-pipeline.ts:63-113`, `src/functions/consolidation-pipeline.ts:158-198`). **Feature-gated but automatic when enabled**. | LLM extraction is entitled to create durable knowledge; repeated corpus evidence substitutes for explicit confirmation. | Conflicts with “nothing self-promotes”; observations require user confirmation to become stated (`../kivi-semantic-memory-position.md:87-101`). Difference pushes toward keeping consolidation outputs observed/hypothesised until confirmation. |
| Should hypotheses be stored as claims, questions, or not at all? | No epistemic hypothesis type exists; generated `SemanticMemory.fact` is declarative with numeric confidence (`src/types.ts:521-532`). **Hardcoded model omission**. | Confidence scalar adequately expresses uncertainty; grammatical form has no enforcement role. | Does not hold. Kivi stores hypotheses as questions and never acts on them without confirmation (`../kivi-semantic-memory-position.md:91-99`). Difference pushes toward a typed, non-actionable hypothesis state. |
| How is recency/use turned into forgetting? | Retention score combines type-weighted salience, exponential age decay, and reciprocal-time access boosts; below-threshold rows are evictable (`src/functions/retention.ts:65-120`, `src/functions/retention.ts:247-313`). **Formula defaults are request-configurable; periodic policy is code/config driven**. | Access implies value; architecture/preferences deserve higher base salience; a single scalar can compare distinct memory kinds. | Only partly holds. Kivi requires observations to decay and hypotheses to expire, but stated facts need correction/supersession semantics rather than generic use-frequency eviction (`../kivi-semantic-memory-position.md:239-247`). Difference pushes toward tier-specific clocks and user pinning. |
| Should retrieval be lexical, semantic, structural, or hybrid? | BM25 is always available; embeddings are opt-in/auto-detected; graph is best-effort. Active streams are fused by weighted RRF and optional reranking (`src/config.ts:254-281`; `src/state/hybrid-search.ts:81-258`). **Weights configurable; fusion/reranking hardcoded**. | Missing streams should not penalize results; rank is more comparable than raw score; local zero-key operation matters. | Kivi leaves retrieval mechanics open (`../kivi-semantic-memory-position.md:267-274`). Repo supplies a precedent, not evidence for Kivi's entity/preference/episode queries. |
| What is ordered first: relevance, recency, confidence, diversity, or authority? | Search orders by fused relevance, breaks ties by minimum stream rank then ID, diversifies across sessions, and reranks only a head window (`src/state/hybrid-search.ts:198-258`, `src/state/hybrid-search.ts:261-289`). **Mostly hardcoded**. | Session diversity improves usefulness; authority/tier is absent; deterministic IDs are an acceptable last tie-break. | Does not encode Kivi's stated > observed > hypothesis action permissions (`../kivi-semantic-memory-position.md:129-179`). Difference pushes toward separating relevance ranking from epistemic eligibility/disclosure. |
| Should the mode gate retrieval or disclosure? | Feature and scope filters gate retrieval; there is no user-facing epistemic mode or withheld-result trace (`src/functions/search.ts:467-599`; `src/types.ts:191-203`). **Architecture omission**. | If a row is ineligible, excluding it is sufficient; caller needs results, not a decision trace. | Kivi explicitly retrieves everything and gates disclosure, recording withheld items (`../kivi-semantic-memory-position.md:155-174`). Difference pushes toward a two-stage retrieve/authorize pipeline with trace output. |
| Should dictation and interactive assistance share retrieval? | AgentMemory exposes common search/context tools across agent surfaces; it has no dictation contract or schema-enforced lexical-only store (`src/mcp/tools-registry.ts:946-980`; `src/state/schema.ts:4-75`). **Not faced / inference from absence**. | All consumers are coding agents with broadly similar memory rights. | Kivi requires structurally separate dictation retrieval limited to lexical/entity memory (`../kivi-semantic-memory-position.md:181-201`). Difference pushes toward separate capabilities, not a filter flag on one query. |
| What does the caller receive on success? | Full or compact ranked records with scores and selected metadata; smart search can include lessons (`src/types.ts:191-203`, `src/types.ts:275-302`; `src/functions/smart-search.ts:274-318`). **API-selectable shapes, fixed schemas**. | Agent callers can interpret scores and source IDs; end-user explanation is outside core API. | Kivi needs a response trace of retrieved, withheld, used, and source transcript items (`../kivi-semantic-memory-position.md:220-229`). Difference pushes toward first-class decision provenance in every response. |
| What happens on low confidence or absent evidence? | Search returns an empty list; vector/graph/rerank failures silently degrade to other streams; lesson recall failure returns no lessons (`src/state/hybrid-search.ts:95-128`, `src/state/hybrid-search.ts:247-258`; `src/functions/smart-search.ts:314-318`). **Hardcoded graceful degradation**. | Availability matters more than distinguishing degraded modes; the caller will formulate any abstention. | Kivi treats abstention and “what I searched” as product behavior (`../kivi-semantic-memory-position.md:203-229`). Difference pushes toward typed absence/degradation reasons rather than an indistinguishable empty result. |
| Which failures may be hidden to preserve the main path? | Index writes, graph lookup, access logging, cascade, and asynchronous post-stop work are often best-effort; the stored row may succeed while indexes lag (`src/functions/remember.ts:193-220`; `src/state/hybrid-search.ts:95-128`; `src/triggers/events.ts:98-145`). **Hardcoded failure policy**. | Eventual rebuild repairs secondary state; capture availability has lower failure cost than stale recall. | Riskier for Kivi because a silent missing provenance, exclusion, or suppression enforcement breaks a trust claim (`../kivi-semantic-memory-position.md:39-50`, `../kivi-semantic-memory-position.md:232-250`). Difference pushes toward fail-closed on policy state while allowing fail-open only on enrichment. |
| What is assumed idempotent and ordered? | Delivery dedup is process-local/TTL; per-session observation writes and global remember operations use keyed in-process locks; consolidation cooldown uses an in-process promise chain plus a KV marker (`src/functions/observe.ts:66-89`, `src/functions/observe.ts:146-155`; `src/functions/remember.ts:71-78`; `src/triggers/events.ts:13-40`). **Hardcoded concurrency scope**. | One worker process is the concurrency authority; restart/multi-worker duplicate windows are acceptable; event timestamps need not establish causal order. | Kivi's confirmation, correction and supersession events require durable idempotency and explicit order/valid-time to prevent old transcripts reasserting stale beliefs (`../kivi-semantic-memory-position.md:232-247`). Difference pushes toward persisted event IDs and causal/version checks. |

## 3. What the history says

Reversals are the highest-value evidence in this repository because they reveal where an initially plausible answer failed under real use.

| Reversal or rewrite | What changed and stated reason | Classification / implication |
|---|---|---|
| **LLM compression: default-on → opt-in** | Every PostToolUse observation had invoked Claude; 50–200 tool calls/hour could burn hundreds of thousands of tokens. The replacement is zero-LLM synthetic compression unless `AGENTMEMORY_AUTO_COMPRESS=true` (`CHANGELOG.md:1048-1058`; current gate `src/config.ts:428-435`). | Deliberate reversal after cost failure, not original design confidence. It says write-path enrichment cost scales with event frequency, not conversation count. |
| **Context injection: automatic → opt-in** | SessionStart added ~1–2K context characters; PreToolUse added useless round trips. Both became gated (`CHANGELOG.md:991-1010`; current gate `src/config.ts:438-448`). | Deliberate reversal after token/latency investigation. The changelog also corrects its own initial diagnosis, which is unusually strong evidence that the precise causal story mattered (`CHANGELOG.md:996-1000`). |
| **Consolidation: explicit off → automatic when an LLM exists** | Current behavior defaults on when any supported LLM configuration is detected, with an explicit false override (`src/config.ts:402-425`; regression contract `test/consolidation-default.test.ts:36-107`). | Deliberate later expansion. It assumes provider presence implies permission to spend on and accept automatic derived memory—a poor proxy for Kivi's user confirmation, but that fit judgment is inference. |
| **Unscoped project memory → scoped new writes, wildcard legacy rows** | Cross-project leakage led to project checks, while missing project remains wildcard for backward compatibility (`CHANGELOG.md:219-220`; `src/functions/remember.ts:118-123`). | Correctness fix constrained by backward compatibility. The wildcard means old rows can still cross project boundaries by design. |
| **Agent isolation abstraction added, then patched across missed paths** | Initial isolation omitted `mem::search`; later fixes applied the same fail-closed rule to search and context after cross-agent leaks (`CHANGELOG.md:85-101`; `test/agent-isolation-search.test.ts:133-190`). | Recurring bug class: policy implemented independently at each read surface. It implies the original boundary abstraction stopped working because authorization was not centralized. |
| **Monolithic graph enumeration → maintained indexes/snapshot** | At 75K+ nodes, `kv.list` produced a 37MB frame, blocked the event loop and killed the worker heartbeat; graph extraction/query were rewritten around O(1) side indexes and a snapshot (`src/state/schema.ts:19-40`; `CHANGELOG.md:105-107`). | Major scale-driven rewrite. This is direct evidence for the repository's practical scale boundary. |
| **Single-call session summary → chunk/map/reduce** | Sessions above ~7,000 observations silently exceeded LLM context; chunking, concurrency and retry were added (`CHANGELOG.md:337-353`; `src/functions/summarize.ts:24-37`). | Scale/provider-limit abstraction added later; the single-session call was incomplete at larger workloads. |
| **In-memory/monolithic index persistence → sharded persistence and dimension guards** | Wrong-dimension vectors silently became unsearchable; large index writes were sharded and restored defensively (`CHANGELOG.md:769`; `src/state/index-persistence.ts:8-38`; `src/index.ts:413-440`). | Recurring “stored but invisible” failure family. Search correctness depends on secondary-state integrity. |
| **Saved memories invisible → unified enrichment fallback** | Search indexed `Memory` rows but enrichment looked only in observation scopes, dropping hits and returning `[]`; `memoryToObservation` unified both paths (`CHANGELOG.md:749`; `src/state/memory-utils.ts:1-38`). | Abstraction added later because two parallel record families diverged. |
| **Retention deleted only episodic namespace → source-discriminated eviction** | Semantic rows below threshold were never deleted because the code targeted `KV.memories`; `RetentionScore.source` and legacy probing were added (`CHANGELOG.md:993-994`; `src/functions/retention.ts:327-334`). | Recurring multi-store lifecycle bug; backward compatibility remains explicit. |
| **Silent deletion → audit policy** | Structural deletion now requires audit rows; forget and sweeps gained batched audit records (`CHANGELOG.md:928`; operation schema `src/types.ts:582-639`). | Deliberate governance abstraction added later, implying original deletion semantics lacked inspectability. |
| **Full paths as project identity → canonical/basename resolution** | Path/basename mismatches filtered out lessons; hooks were changed to use a resolver (`CHANGELOG.md:219`). Worktrees still generated an issue because temporary paths fracture identity. | Recurring identity-model bug; project identity remains context-dependent rather than a stable entity. |

Recurring bug reports cluster around: data successfully stored but not retrievable (`CHANGELOG.md:749`, `CHANGELOG.md:769`); policy applied to one retrieval surface but not another (`CHANGELOG.md:85-101`); environment/documented configuration silently ignored (`CHANGELOG.md:337-347`, `CHANGELOG.md:834`); and “success” while persistence or connector wiring failed (`CHANGELOG.md:689`, `CHANGELOG.md:266`). These are not four separate algorithms; they are repeated boundary-consistency failures—an inference supported by the cited incidents.

The code contains few literal TODO/FIXME markers. The meaningful admitted shortcuts are comments: best-effort graph/vector/index paths (`src/state/hybrid-search.ts:95-128`; `src/functions/remember.ts:193-197`), unscoped legacy memories treated as wildcards (`src/functions/remember.ts:118-123`), old retention rows probed across both stores (`src/functions/retention.ts:327-334`), and graph-reset leaving legacy rows as on-disk orphans (`CHANGELOG.md:105-107`). These are explicit compatibility or availability tradeoffs, not evidence of a considered end-state.

## 4. Unexamined defaults

| Default with no visible deliberation | Alternative not tried in this repository |
|---|---|
| Every explicit memory originates as `agent`, even when an MCP caller may be relaying a user's direct statement (`src/functions/remember.ts:152-171`). | Require caller-declared actor/consent and preserve the exact utterance-to-claim relationship. |
| Missing/invalid memory type silently becomes `fact` (`src/functions/remember.ts:50-60`). | Reject unknown types or store `unclassified` until reviewed. |
| A numeric confidence/strength scalar stands in for epistemic status (`src/types.ts:521-532`; `src/functions/consolidate.ts:56-58`). | Separate source authority, evidence count, uncertainty and action permission. |
| First above-threshold candidate wins supersession (`src/functions/remember.ts:116-134`). | Compare all candidates, require unique identity, or return an ambiguity set. |
| Lexical tokens of length ≤2 are discarded for non-CJK text (`src/state/schema.ts:102-105`). | Preserve domain abbreviations such as AI/ML/DB with a different tokenizer. |
| Missing project on either side is a wildcard (`src/functions/remember.ts:118-123`). | Treat unknown scope as quarantined/fail-closed and migrate explicitly. |
| Access frequency reinforces truth/value (`src/functions/retention.ts:65-120`). | Treat access as popularity only, leaving validity independent. |
| Preference is more salient than bug, workflow, or fact by fixed type weight (`src/functions/retention.ts:103-112`). | Learn weights per user/task or avoid cross-type scalar comparison. |
| Retrieval failures degrade silently to fewer modalities (`src/state/hybrid-search.ts:95-128`, `src/state/hybrid-search.ts:247-258`). | Return degraded-mode metadata or abstain when a required modality is unavailable. |

## 5. Questions this repository never faced

These questions arise directly from Kivi's product commitments, not from missing AgentMemory features.

1. How is the speaker/subject/owner of every clause identified so Priya's personal fact can be used transiently but never become Meera's memory? AgentMemory records channel, not subject or consent (`src/types.ts:30-45`), while Kivi requires “read, not kept” semantics (`../kivi-semantic-memory-position.md:106-126`).
2. What is the enforceable relationship between entity/preference/episode and stated/observed/hypothesised, including invalid combinations and action permissions? AgentMemory's taxonomies do not express that cross-product (`src/types.ts:85-125`, `src/types.ts:515-548`); Kivi makes it central (`../kivi-semantic-memory-position.md:66-104`).
3. What event proves explicit confirmation, and how is silence prevented from becoming confirmation? No confirmation-event type exists in the audit union (`src/types.ts:582-633`); Kivi says silence never confirms (`../kivi-semantic-memory-position.md:203-218`).
4. How is a hypothesis grammatically and programmatically prevented from being consumed as a fact? AgentMemory stores declarative semantic facts with confidence (`src/types.ts:521-532`); Kivi requires questions that cannot accidentally act as claims (`../kivi-semantic-memory-position.md:91-99`).
5. How are excluded candidates logged without retaining the sensitive content needed to explain the exclusion? AgentMemory redacts matching substrings but has no candidate/drop record (`src/functions/privacy.ts:3-39`); Kivi promises counts and reasons (`../kivi-semantic-memory-position.md:39-50`).
6. What is the durable suppression key for “that's not me anymore” when wording, entity aliases, or extraction models change? AgentMemory deletion has no tombstone in `Memory` (`src/types.ts:102-125`); Kivi requires suppression against re-derivation (`../kivi-semantic-memory-position.md:239-247`).
7. How are valid-time and transaction-time separated when “the review moved from Thursday to Tuesday” is both an episode and a correction? AgentMemory has created/updated timestamps and version links but no validity interval (`src/types.ts:102-125`); Kivi's examples require temporal change (`../kivi-semantic-memory-position.md:74-83`, `../kivi-semantic-memory-position.md:239-244`).
8. How can dictation physically lack access to observation/hypothesis tables while Hey Kivi can retrieve them? AgentMemory offers shared namespaces and retrieval functions (`src/state/schema.ts:4-75`); Kivi requires two structural paths (`../kivi-semantic-memory-position.md:181-201`).
9. How does an answer trace distinguish retrieved, withheld, used, rejected, and absent evidence without leaking withheld sensitive content? AgentMemory result schemas return records/scores but no use/withhold trace (`src/types.ts:191-203`, `src/types.ts:275-302`); Kivi promises that trace (`../kivi-semantic-memory-position.md:220-229`).
10. What weekly confirmation budget mechanism selects the highest-value uncertain memory, and what fairness or starvation behavior follows? AgentMemory has no confirmation budget model; Kivi leaves its size open but commits to budgeting (`../kivi-semantic-memory-position.md:211-218`, `../kivi-semantic-memory-position.md:267-274`).
11. What does “never infer permission from tone” mean at API boundaries when Daari is a one-request escalation and its answer must not be written? AgentMemory has no inference-permission request scope (`src/types.ts:179-203`); Kivi requires it (`../kivi-semantic-memory-position.md:155-174`).
12. How are provenance views made legible to a non-developer while source transcripts may themselves contain third-party material that cannot be retained or redisplayed? AgentMemory's viewer/API orientation is record-centric (`src/types.ts:47-125`); Kivi requires one-tap source provenance and third-party deletion simultaneously (`../kivi-semantic-memory-position.md:106-126`, `../kivi-semantic-memory-position.md:232-250`).
