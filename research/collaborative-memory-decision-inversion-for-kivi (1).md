# Collaborative Memory, Inverted for Kivi

This document inverts the design choices in Rezazadeh et al., *Collaborative Memory: Multi-User Memory Sharing in LLM Agents with Dynamic Access Control* (arXiv:2505.18279v1), against the Kivi position document. It maps decision space; it does not recommend answers.

## Reading key

- **Paper answer** reports what the authors built or evaluated, not what their abstract framework could theoretically support.
- **Alternatives** includes both explicitly rejected options and plausible options the paper does not test. Where the paper does not report considering them, that is stated.
- **Fit for Kivi** compares the paper's assumption with Kivi's stated design. **Underspecified** means the Kivi position explicitly leaves the issue open or does not supply enough information.
- **Load-bearing** means changing the answer would materially alter the paper's claimed privacy, efficiency, or accuracy results.
- Paper links use PDF page numbers. Kivi references point to sections of the attached position document.

## 2. Forced choices

These are the paper's load-bearing decisions: replacing them would materially change what its experiments demonstrate.

| Decision | Why load-bearing in this paper | What result would move if answered differently |
|---|---|---|
| **F1 — Share across users or isolate (D01)** | The treatment variable in Scenarios 1 and 2 is collaborative versus isolated memory. | The reported 59–61% reductions in resource use at high overlap and the Scenario 2 histograms would disappear or change fundamentally. |
| **F2 — Current graph + provenance determines eligibility (D02–D03)** | The central security claim depends on filtering every fragment by current user→agent and agent→resource permissions. | The access matrices and “strict adherence” claim in Scenario 3; revocation behavior. |
| **F3 — Private/shared two-tier partition (D04)** | Cross-user reuse is measured by drawing separately from user-specific and shared stores. | Cross-memory utilization, the isolated/collaborative comparison, and privacy interpretation. |
| **F4 — Transform intermediate responses into shared key–value memory (D05–D10)** | Resource savings require agent outputs to become reusable fragments; privacy claims rely on the transformation prompt removing user-specific detail. | Both efficiency and privacy. Storing only raw or final responses, or requiring approval, changes availability and cost; failed transformation changes confidentiality. |
| **F5 — Fixed top-*k* semantic retrieval over fragment keys (D15–D16)** | A later query avoids a resource call only if the prior fragment is retrieved into context. | Accuracy, resource calls, and cross-user reuse rates. No retrieval ablation isolates this effect. |
| **F6 — Memory-first, tools-if-insufficient behavior (D20)** | The reported efficiency gain counts avoided resource calls; agents are explicitly prompted to prefer memory. | Resource utilization is directly sensitive to the reuse threshold, even at identical answer quality. |
| **F7 — LLM coordinator controls authorized specialist selection (D18)** | Agent access translates into actual resource access only through routing. | Accuracy and agent/resource utilization under every scenario. |
| **F8 — Accumulate memory across repeated/evolving query blocks (D13)** | Scenario 3 reuses the same 100 queries at multiple graph states while memory accumulates. | Falling resource use over time and interpretation of dynamic revocation; a fresh store per state would test a different phenomenon. |
| **F9 — Reuse overlapping or semantically related queries (dataset design)** | Scenario 1 explicitly manufactures overlap; Scenario 3 repeats the same queries. | The opportunity for memory reuse, hence the headline resource-saving result. |
| **F10 — Call count as the efficiency measure (D28)** | The strongest empirical benefit is fewer resource calls, not measured end-to-end latency or cost. | Whether the framework is actually more efficient after coordinator, embedding, write-transform, retrieval, and aggregator costs are included. |

For Kivi, the most consequential forced-choice transfer failures are F1, F4, F6, F8, and F9: the paper's gains arise in a different reuse economy—cross-user answers to overlapping information tasks—than Kivi's removal of repeated personal briefing.

## 4. Questions the paper never faced

These arise from Kivi's users, product contracts, and failure costs—not from gaps in collaborative-memory benchmarking.

1. **When text contains both the user's words and another person's words, what should determine which propositions are eligible even to become memory candidates?** Kivi sees Slack/email context and dictation in one turn; the other person never consented.
2. **When work-level residue is derived from third-party personal content, how much derivation is enough to make retention legitimate and non-identifying?** “Meeting moved” and “person is absent” can remain linked even after explicit details are dropped.
3. **When the same interaction supports an entity fact, a preference pattern, and a psychological inference, where exactly should extraction stop?** Kivi commits to the first two under different authority and rejects the third.
4. **When a candidate falls near an excluded category boundary—work finance versus personal finance, project stress versus mood—what should determine exclusion, and what evidence may the boundary checker inspect or retain?**
5. **When an excluded candidate is logged, how can the log prove enforcement without itself retaining the sensitive proposition?** Kivi wants a visible dropped-candidate reason, creating a metadata leakage question.
6. **When repeated behavior supports an observation, what denominator, diversity of contexts, and recency make the evidence count meaningful?** Fourteen near-duplicate email edits are not necessarily fourteen independent observations.
7. **When a user confirms an observation, is the confirmed rule global, recipient-specific, surface-specific, or task-specific?** “Client emails in prose” has an audience and context.
8. **When a user corrects a memory during a task, should the current output be regenerated, merely continue with the correction, or expose that prior text used the old belief?**
9. **When “That's not me anymore” suppresses re-derivation, what semantic scope should the suppression cover without blocking genuinely new future behavior?** Exact strings are too narrow; broad embedding neighborhoods may become a permanent blind spot.
10. **When “Forget” conflicts with retained source transcripts or extraction logs, what must be deleted, tombstoned, or made unreachable?** Kivi promises removal plus suppression while also promising provenance.
11. **When a source transcript is edited or deleted, what happens to every memory, observation, evidence count, confirmation, and response trace derived from it?**
12. **When two sources contradict, what should determine whether the old memory was wrong, has changed over time, applies in a different context, or reflects ambiguity?**
13. **When a stated preference conflicts with current behavior, should Kivi obey the statement, surface the drift under Koottu, or ask for reconfirmation?**
14. **When an observation is retrieved under Anbu but withheld, how much can the “Kivi noticed something” affordance reveal without violating the chosen permission?** Even the existence of a pattern can be disclosure.
15. **When Daari is invited for one answer, what should prevent its hypothesis from leaking into later retrieval, logs, summaries, analytics, or model-generated memories?** Kivi says the answer is not written to memory, but secondary traces remain a design question.
16. **When tone sounds like an invitation but the user did not use an explicit trigger, what exact interaction counts as per-request Daari permission?** The position rejects tone inference but gives examples rather than a complete protocol.
17. **When dictation and Hey Kivi share entity/lexical memory, how should the architecture prove that observation and hypothesis stores cannot be reached by the dictation path—including through shared caches or orchestration prompts?**
18. **When lexical memory improves transcription, what happens if the remembered spelling is wrong and silently changes the user's actual words?** This is a distinct failure from an incorrect Hey Kivi answer.
19. **When Kivi abstains, what evidence can it expose about “what it looked for” without revealing withheld or excluded memories?** Search transparency and disclosure control can conflict.
20. **When the nearest related memory concerns another person or a lower-permission tier, should abstention mention its existence, its metadata, neither, or ask for escalation?**
21. **When confirmation prompts are scarce, what should define “highest-value” uncertainty: expected reuse, failure cost, user annoyance, evidence quality, or opportunity to prevent harm?** The weekly budget and allocation rule are open.
22. **When the user never opens the Why panel, what observable evidence shows that the control is understood rather than merely available?**
23. **When the user edits Kivi's belief, is that edit itself a source, an override, a new stated memory, or a policy instruction—and how is it shown in provenance?**
24. **When a project, person, or preference spans work and personal life, what determines whether the work-level exception still applies?**
25. **When a memory helps draft a message to another person, how should Kivi distinguish using a fact about the user's world from characterizing or manipulating the recipient?**
26. **When an old observation decays, should its evidence remain visible in history, continue to affect ranking, or become inaccessible except during audit?**
27. **When a model upgrade changes extraction decisions, should old transcripts be reprocessed, and if so, how are prior exclusions, suppressions, and confirmations preserved?**
28. **When Kivi is wrong in a way that reaches an external action—wrong recipient, schedule, or client claim—what recovery surface and attribution should the user get?** The paper only answers informational QA.

## 5. Evaluation gap

### What the paper measured

| Scenario | Data and manipulation | Measurements actually reported | What it establishes narrowly |
|---|---|---|---|
| **1: Fully collaborative** | 2,556 MultiHop-RAG questions over 609 English news articles; five users; six agents/resources; manufactured overlap rates 0/25/50/75%; shared versus isolated memory. | LLM-judged normalized accuracy; mean distinct agents; mean resource calls over query order. | Under repeated/overlapping benchmark queries, generated fragments can substitute for resource calls without a large measured accuracy penalty. |
| **2: Asymmetric** | 200 GPT-4o-generated business objectives; four synthetic roles with nested access; four agents and GPT-4o-simulated tools; shared versus isolated. | Resource-call histograms. No ground-truth accuracy because questions are open-ended. | Partial sharing is associated with fewer tool calls in this synthetic workflow. It does not establish answer quality or confidentiality. |
| **3: Dynamic** | 100 SciQAG questions, five users/categories/agents/resources; same questions replayed across graph states; grants then revocations; memory accumulates. | Accuracy, agent calls, resource calls, counts of user/cross fragments, and access/usage matrices. | Agent/resource invocation follows the configured graph in the observed runs; accumulated memory reduces calls while available agents affect accuracy. |

The paper says it measures “privacy compliance,” but it does not define a standalone privacy metric, report leakage/adversarial tests, measure re-identification, or quantify transformation failures. The visible evidence is that agent/resource **usage** occurs only under granted graph edges (Scenario 3/Figs. 6 and 11). That does not test whether a permitted fragment itself contains information that should not have been shared, whether the write transform leaks identity, or whether unauthorized content influences an answer through another derived fragment. The authors themselves note that probabilistic LLMs may cause policy breaches (§6).

### Decisions its metrics cannot distinguish

| Indistinguishable alternatives under the reported evaluation | Decision IDs | Why both can score the same |
|---|---|---|
| Prompt-redacted shared memory vs deterministic redaction vs explicit contributor approval | D06, D07, D10 | Accuracy and call count do not measure leaked personal attributes, consent, or false anonymization. |
| Agent/resource graph policy vs per-memory ACL vs subject/purpose policy | D02–D04 | On synthetic homogeneous corpora, all can permit the same calls and return the same answers. The matrices inspect invocations, not semantic authorization. |
| Current-time hiding vs deletion/cryptographic revocation/downstream invalidation | D03, D14, D27 | The test sees whether currently blocked agents/resources are called; it does not probe old outputs, caches, copies, or recoverability. |
| Key–value fragments vs typed entities/preferences/episodes vs source-linked atomic claims | D05, D08–D09, D25 | If the answer text is retrieved, normalized accuracy and call count do not reveal whether future correction, explanation, or epistemic gating is possible. |
| Append contradictions vs supersede/version/ask the user | D11–D13 | The datasets do not introduce controlled contradictions, identity change, or long-duration staleness. |
| Key-only cosine similarity vs hybrid/graph/recency/evidence-aware ranking | D15–D16 | Aggregate answer accuracy may match while retrieved evidence quality, stability, and explainability differ; no retrieval precision/recall or ranking ablation is reported. |
| Retrieve-then-disclose gate vs least-privilege retrieval | D17, D23 | The paper measures final calls and answers, not whether withheld content entered model context or influenced generation. |
| Silent synthesis vs explicit disagreement/citations | D19, D22 | A judge can score the same final answer even if one preserves provenance and the other obscures conflict. No user comprehension/trust metric exists. |
| Memory-first substitution vs authoritative re-check for mutable facts | D20 | Repeated short-horizon benchmark questions reward reuse; no freshness or changed-ground-truth condition tests stale answers. |
| Calibrated abstention vs plausible completion vs nearest-memory answer | D21 | Although MultiHop-RAG includes null queries, no reported abstention calibration, false-answer cost, or search-trace quality separates policies. |
| Persistent permission mode vs per-request invitation vs inferred permission | D26 | No user-facing inference/disclosure permission exists in the evaluation. |
| A visible user correction/suppression surface vs administrator-only policy updates | D14, D22, D27 | No users inspect, correct, forget, or contest stored beliefs. |
| Two structurally separate product retrieval paths vs one path with a filter | D17, D24 | The paper contains only agentic QA, not a transcription surface with a different user contract. |
| Low call count vs low latency/cost | D28 | Embedding, coordinating, transformation, retrieval, and aggregation costs are not totaled; equal call counts can have very different end-to-end cost and tail latency. |
| Cross-user factual cache vs personal semantic memory that avoids re-briefing | D01, D05, D20 | The paper's overlap/replay makes old answers reusable. It does not measure personal continuity, re-explanation burden, or the cost of a wrong belief about the user. |

### Evidence the paper provides—and does not provide—for Kivi's committed demonstrations

| Kivi claim to demonstrate | Evidence from this paper |
|---|---|
| Excluded-category candidate extracted, dropped, and reason logged | **None.** Write prompts transform; rejected-candidate logging is unspecified. |
| Third-party personal content used transiently but not retained | **None.** No third-party/subject consent condition or storage audit. |
| Memory assembled from evidence across separate dictations | **Weak precedent only.** Fragments summarize interactions and are reused, but no typed multi-evidence personal observation is evaluated. |
| Same observation withheld under Anbu and surfaced under Koottu | **None.** No separation of retrieval and disclosure or epistemic tier. |
| Abstention on absent answer with visible search trace | **None.** Null questions exist, but this behavior and trace are not reported. |
| Correction demotes a memory and it does not regrow | **None.** No correction, suppression, reprocessing, or anti-rederivation test. |
| Dictation path structurally cannot load observations | **None.** There is no dictation path or multi-surface access test. |

## Scope boundary

The Kivi position document deliberately leaves storage/retrieval mechanics, extraction timing, decay windows, confirmation budget, evidence thresholds, cost/latency targets, and the exact Hey Kivi tool set unresolved (Kivi Appendix B). Those items are therefore marked **underspecified** rather than inferred from the paper or filled in here.
