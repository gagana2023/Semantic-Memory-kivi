# CoALA Inverted: The Design Questions Behind *Cognitive Architectures for Language Agents*

**Paper:** Theodore R. Sumers, Shunyu Yao, Karthik Narasimhan, and Thomas L. Griffiths, *Cognitive Architectures for Language Agents* (CoALA), TMLR 2024, [arXiv:2309.02427v3](https://arxiv.org/html/2309.02427v3).

**Target setting:** Kivi, as specified in *The Things Kivi Comes to Know*: a text-based assistant whose semantic memory is calibrated, excludes third-party and sensitive personal material, distinguishes stated facts from observations and hypotheses, preserves provenance and reversibility, separates dictation from interactive “Hey Kivi” use, and exposes retrieval/use/withholding to the user.

## Reading discipline

CoALA is a conceptual framework and retrospective survey, not a single implemented system. “The paper answered” below therefore means “the framework commits to this decomposition or design stance.” Where CoALA merely lists options, the row says **underspecified**. The Kivi-fit column tests CoALA’s assumptions against the attached position note; it does not recommend a choice.

This is both a UX-contract and safety distinction outside CoALA’s abstraction. | [§4.3](https://arxiv.org/html/2309.02427v3#S4.SS3), [§6 “Agent design”](https://arxiv.org/html/2309.02427v3#S6) |

## 2. Forced choices

These are the decisions for which changing CoALA’s answer would materially alter the framework, its case-study comparison, or the architectural consequences drawn for Kivi.

1. **LLM-as-component, not LLM-as-agent (D1).** CoALA’s thesis depends on an architecture outside the model. Remove that boundary and its memory/action/decision vocabulary stops being a system decomposition.
2. **Memory–action–decision as the organizing frame (D2).** Table 2 and the retrospective comparison of SayCan, ReAct, Voyager, Generative Agents, and Tree of Thoughts are produced by this partition. A privacy-, dataflow-, or user-control-first partition would organize the literature differently.
3. **Explicit working and long-term memory modules (D3–D4).** Without persistent working state and differentiated long-term stores, retrieval, learning, and multi-cycle decisions cannot have CoALA’s meanings.
4. **Retrieval, reasoning, and learning as different actions (D7, D9, D10).** This separation is what makes a memory read different from an inference and a durable write. Collapsing them would erase the framework’s most useful write boundary for Kivi.
5. **A planning/execution decision loop (D13).** CoALA’s “cognitive” agent is more than a prompt chain because it selects and executes actions in feedback loops. A fixed pipeline would materially narrow the claimed generality.
6. **Procedural memory and self-modification are in scope (D11).** Voyager’s placement and the paper’s lifelong-learning agenda rely on learned skills/code being memory. Excluding procedural mutation would reduce both the taxonomy and its prospective claims.
7. **Action-space size trades off against controller complexity and risk (D16).** This underlies the paper’s concrete design advice. If a universal action interface were sufficient, the recommendation to start minimal would disappear.
8. **Code is sparse scaffolding around model flexibility (D17).** This is the paper’s implementation stance. Kivi’s hard product promises make the boundary itself a forced choice: moving exclusions, suppression, or access control into stochastic behavior changes what can be demonstrated.
9. **Lifecycle semantics are not supplied (D18).** This is load-bearing by absence for Kivi. Accumulation-oriented memory can appear successful in the surveyed tasks while failing Kivi’s revisability promise.
10. **Failure/disclosure/ownership are outside the core framework (D19–D22).** These omissions do not damage CoALA’s survey purpose, but they prevent the framework alone from specifying Kivi. Filling them changes the effective architecture more than swapping BM25 for dense retrieval would.

## 3. Unexamined defaults

These choices are mostly inherited from the agent literature. “Unexamined” means CoALA uses or reproduces the default without making it a central design question.

| Default inherited by the paper | Where it appears | Alternative this line of work rarely centers |
|---|---|---|
| **Agent state is organized by cognitive function, not by data rights.** | Episodic/semantic/procedural modules in [§4.1](https://arxiv.org/html/2309.02427v3#S4.SS1). | Partition memory first by data subject, consent, purpose, sensitivity, and disclosure entitlement; cognitive type becomes secondary metadata. |
| **Text is the universal interchange representation.** | Text as de facto internal representation and grounding as a “text game” in [§4](https://arxiv.org/html/2309.02427v3#S4) and [§4.2](https://arxiv.org/html/2309.02427v3#S4.SS2). | Preserve typed events, speaker identity, temporal validity, provenance, and access labels end-to-end; render text only at the model boundary. |
| **A retrieved memory is eligible context.** | Retrieval moves long-term information into working memory in [§4.3](https://arxiv.org/html/2309.02427v3#S4.SS3). | Treat retrieval, generation eligibility, action eligibility, and disclosure as four independently logged gates. |
| **Learning is primarily additive.** | Multiple ways to write memories and skills are enumerated before modification/deletion is noted as understudied in [§4.5](https://arxiv.org/html/2309.02427v3#S4.SS5). | Make contradiction, expiry, correction, redaction, suppression of re-learning, and provenance repair first-class before permitting accumulation. |
| **Successful task behavior is the natural objective.** | Proposal/evaluation chooses actions by heuristic, model, learned, or simulated values in [§4.6](https://arxiv.org/html/2309.02427v3#S4.SS6). | Optimize lexicographically: rights and hard constraints first, epistemic validity second, task utility third, convenience last. |
| **The environment and external action space are “given.”** | Stated explicitly in the retail-assistant design recipe in [§6](https://arxiv.org/html/2309.02427v3#S6). | Treat the product contract—what the user thinks they invoked—as determining permissible memory, tools, latency, and disclosure for that turn. |
| **The agent is the unit of analysis.** | One working memory, long-term memories, action space, and decision procedure throughout [§4](https://arxiv.org/html/2309.02427v3#S4). | Treat each data subject and each interaction surface as a separate authority domain, even when one assistant spans them. |
| **Summarization is benign compression.** | End-of-interaction episodic summary in the retail example, [§6](https://arxiv.org/html/2309.02427v3#S6). | Store claims and evidence separately; evaluate whether summaries introduce inference, erase contradiction, or lose the basis for correction. |
| **Feedback is evidence of outcome, not necessarily consent.** | Environmental feedback closes the decision loop in [§4.6](https://arxiv.org/html/2309.02427v3#S4.SS6). | Represent silence, acceptance of an output, correction, and explicit confirmation as distinct events that grant different memory rights. |
| **Safety is mainly action-space harm.** | Internal procedural harm and external grounding harm in [§6 “Safety of the action space”](https://arxiv.org/html/2309.02427v3#S6). | Treat a true but improperly retained or disclosed personal fact as a safety failure even when no external tool action occurs. |
| **Inspectability is for builders.** | The framework standardizes concepts and implementations for research/industry in [§6 “Modular agents”](https://arxiv.org/html/2309.02427v3#S6). | Make the user-facing explanation and correction surface the canonical observability layer, with engineering traces derived from it. |

## 4. Questions the paper never faced

These come from Kivi’s users, contracts, and failure modes—not from gaps guessed abstractly from CoALA.

### Intake and representation

- When one input combines the user’s dictation with quoted application context from another person, what should determine which spans are eligible even to become candidate memories?
- When a useful work fact is derived from third-party content, what transformation makes it “work-level residue” rather than retained third-party information, and how is that boundary testable?
- When a transcript supports both a fact and a characterization, what should decide whether the candidate is an entity/preference/episode or a prohibited inference about competence, character, health, mood, relationships, faith, politics, or finances?
- When source text is summarized, what minimum evidence must remain so the user can verify and reverse each resulting belief?
- When names, projects, and people are ambiguous, what evidence is sufficient to merge mentions into one entity rather than keep them separate?

### Write path and epistemics

- When the same proposition is explicitly stated once and behaviorally observed many times, what should determine its tier, and can one claim carry more than one tiered evidence path?
- When an observation has many examples, why does frequency increase evidence without increasing permission, and how should the schema prevent accidental self-promotion?
- When a hypothesis is useful for one invited answer, what should ensure it is not silently written, reused, or treated as a claim?
- When a user says nothing after a hypothesis or correction prompt, what—if anything—may be learned from silence?
- When excluded material is dropped, what may the audit log retain about the drop without itself becoming a side channel for the forbidden content?

### Conflict, change, and forgetting

- When two stated memories contradict, what should determine whether the new one supersedes the old, applies to a different context, or requires clarification?
- When an observed pattern stops recurring, what combination of elapsed time, opportunity to observe, and counterevidence should cause decay?
- When the user says “that’s not me anymore,” what exactly is suppressed: the wording, the proposition, the evidence pattern, the category of inference, or all future re-derivations from named sources?
- When “forget” conflicts with the need for an auditable history, what minimal tombstone can prevent re-derivation without preserving what the user asked to remove?
- When a correction itself is later corrected, how should provenance and authority be represented without turning the user into a database administrator?

### Retrieval, use, and disclosure

- When the same underlying memory is reachable from ordinary dictation and Hey Kivi, what should determine whether access is structurally impossible, merely filtered, or allowed but withheld from disclosure?
- When the permission dial governs disclosure rather than retrieval, which components may see withheld content, and how is leakage through reasoning or phrasing detected?
- When relevance conflicts with epistemic tier, recency, source quality, or disclosure permission, what ranking or gate happens first?
- When an answer requires combining several distributed memories, what makes the composition attributable rather than a new unsupported inference?
- When Kivi retrieves nothing, what search coverage must it expose for an abstention to be informative without revealing withheld material?

### User surface and failure recovery

- When should Kivi interrupt the task to ask for confirmation, given that confirmation improves memory but consumes a deliberately limited user-attention budget?
- When a memory is wrong but the final response happens to be acceptable, how can the user discover and repair the latent error before it matters later?
- When a user opens “Kivi noticed something here,” does one-time disclosure change permission, confirm the observation, or do neither?
- When a memory causes harmful output, which action should repair the past response, the stored claim, its evidence, and the extractor behavior that produced it?
- When the Why panel must serve both ordinary users and engineers, what information is necessary for recourse yet safe and comprehensible enough to expose?

### Time, scale, cost, and product boundaries

- When the history becomes large, what may be compacted or discarded without breaking provenance, contradiction detection, suppression, and “show what you searched”?
- When latency or cost forces partial retrieval, what should Kivi say about incomplete search rather than presenting an answer as exhaustive?
- When a project, employer, or relationship changes, what scopes prevent old work context from bleeding into a new one?
- When a user exports, resets, or leaves, what objects must travel or disappear together: memories, evidence, suppression rules, traces, and derived indexes?
- When multiple users appear in a shared workspace, whose memory is Kivi’s, who can correct it, and whose permission dial controls disclosure?

## 5. Evaluation gap

### What the paper measured

CoALA reports **no original system experiment, benchmark, user study, ablation, or quantitative evaluation**. Its evidence is:

- conceptual correspondence between production systems, cognitive architectures, prompting, and language agents ([§§2–4](https://arxiv.org/html/2309.02427v3));
- retrospective classification of five representative agents by long-term memory, grounding, internal actions, and decision-making (Table 2 and [§5](https://arxiv.org/html/2309.02427v3#S5)); and
- summaries of results reported in the cited source papers—for example, Voyager’s exploration, tech-tree mastery, and zero-shot task generalization with procedural-memory ablations ([§5](https://arxiv.org/html/2309.02427v3#S5)).

Thus, CoALA evaluates mainly **descriptive coverage and conceptual usefulness**. It does not test the framework’s own design choices against alternatives.

### Decisions its evidence cannot distinguish

|---|---|---|

### What the cited case-study metrics do establish—and what they do not

- **SayCan-style task completion/groundedness** can distinguish action-selection competence, but not memory ownership, provenance, contradiction handling, or disclosure policy.
- **ReAct-style task success** can distinguish whether interleaving reasoning and acting helps, but not whether reasoning should be retained or shown.
- **Voyager exploration, tech-tree, and generalization results** provide evidence that learned procedural memory can improve an open-ended game agent. They do not distinguish safe from unsafe self-modification in Kivi.
- **Generative Agents’ believable behavior and reflection architecture** can make episodic-to-semantic synthesis visible, but does not establish that inferred personal claims are verifiable, correctable, consented to, or non-harmful.
- **Tree of Thoughts reasoning success** can test deliberate search over candidate thoughts, but says nothing about durable memory, data rights, user control, or longitudinal change.

### Bottom line

For Kivi, CoALA supplies a useful **map of computational components** and a vocabulary for separating retrieval, reasoning, learning, grounding, and decision-making. It supplies **precedent, not evidence**, for almost every decision involving personal semantic memory: what is eligible to persist, whose data may be retained, how confidence and permission differ, how conflicts age and resolve, how forgetting sticks, what users see, and how abstention should work. Two Kivi designs can share the same CoALA diagram and score identically under every evaluation discussed in the paper while differing completely on Kivi’s core trust claims.
