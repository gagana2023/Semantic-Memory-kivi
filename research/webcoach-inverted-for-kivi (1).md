# WebCoach inverted: the questions behind the design

**Paper:** Genglin Liu et al., “WebCoach: Self-Evolving Web Agents with Cross-Session Memory Guidance,” ICLR 2026, arXiv:2511.12997v2 ([paper](https://arxiv.org/pdf/2511.12997)).  
**Target setting:** Kivi, as specified in *The Things Kivi Comes to Know*: a text-based assistant whose semantic memory is work-scoped, attributable, correctable, explicitly tiered, structurally excludes third-party personal content, and separates retrieval from disclosure.

## Reading boundary

This is an inversion, not an adoption plan. “Holds for Kivi?” compares the assumption behind WebCoach’s answer with Kivi’s stated position; it does not choose an answer for Kivi. Where the paper does not specify a behavior, the inventory says **underspecified**.

## 1. Decision inventory

The **FC** marker identifies load-bearing choices, expanded in §2.

## 2. Forced choices

These are load-bearing for the paper’s reported result or for the identity of the proposed system. A different answer would materially change what was stored, what reached the agent, or what the evaluation could attribute to “memory.”

| ID | Load-bearing choice | Why changing it changes the result materially |
|---|---|---|
| D1 | Completed episodes are the write boundary. | The dynamic condition’s corpus size, cleanliness, and online growth all follow from this boundary. Storing partials or selectively filtering completed runs changes both retrieval supply and the meaning of self-evolution. |
| D2 | Generated summaries are the common representation. | Both retrieval and coaching operate on Condenser text; compression errors propagate into candidate selection and advice. Raw, atomic, structured, or multimodal memory would be a different information channel. |
| D4 | Memory is episodic rather than semantic/claim-level. | Cross-task analogy is the mechanism under test. A fact store, skill library, or consolidated pattern store would test a different hypothesis and would behave differently under contradiction and repetition. |
| D6 | Semantic top-K retrieval selects evidence. | The Coach can only use what retrieval supplies. Structured, temporal, domain-restricted, or learned retrieval could change both gains and harms, especially on semantically similar but procedurally different tasks. |
| D9 | Conflicts are left to implicit downstream reasoning. | Explicit supersession or contradiction handling would alter which advice survives UI drift and accumulated failures. The dynamic-memory claim depends on old and new episodes coexisting without a tested truth-maintenance layer. |
| D11 | Coaching runs at every step. | The intervention opportunity set and large latency overhead both depend on per-step calls. Start-only or error-triggered coaching could materially change success, steps, and time. |
| D12 | A separate LLM selectively intervenes. | The paper attributes gains to the WebCoach stack, but the Coach is both a reasoner and a gate. Always-inject, actor-pull, or deterministic gating would change context load and false-advice frequency. |
| D16 | “Self-evolution” means append-only self-experience. | Dynamic EMS is the strongest condition. Replacing accumulation with consolidation, correction, decay, or policy learning changes the main experimental contrast. |
| D18 | End-state success is the primary arbiter. | The paper’s conclusion follows because some models finish more tasks. Metrics for advice error, privacy, calibration, staleness, or human control could reverse the judgment about the same system. |

## 3. Unexamined defaults

These choices are present in the implementation or framing but are not treated as questions in the paper.

| Default the paper inherits | Alternative this line of work rarely tests | Why it matters here | Evidence |
|---|---|---|---|
| More stored experience is presumptively better. | A memory system whose objective includes justified forgetting, non-retention, and bounded knowledge—not only recall. | Kivi treats refusing to know and allowing the user to outgrow a belief as first-class success states. | §2.2 opening; §2.3 closing; §6 |
| A completed trajectory is a legitimate unit of ownership and reuse. | Subject-scoped memory in which different people appearing in one trace have different retention rights. | Web logs are treated as agent experience; Kivi’s transcripts can contain non-consenting third parties. | §2.1 “Routing”; §2.2 |
| Natural-language summaries are neutral compression. | Representation whose grammar encodes epistemic status and prevents a pattern, hypothesis, or question from silently becoming a fact. | The Condenser can turn interpretation into durable prose without a tier or entitlement marker. | §2.1 “Processing”; Appendix A |
| Similarity is the first definition of relevance. | Eligibility before relevance: permission, subject, status, temporal validity, and suppression decide what may be considered before semantic scoring. | Kivi’s hardest requirements are hard barriers, not ranking preferences. | §2.2 “Retrieval” |
| Retrieved evidence may be transformed into privileged hidden instruction. | Memory influence that remains typed, inspectable, and explicitly lower authority unless confirmed. | A system message erases the distinction between “past pattern,” “trusted rule,” and “speculation.” | §2.3 “Injection mechanism” |
| The agent’s success is the user’s success. | Evaluation where a correct outcome can still fail because the system retained forbidden data, used an unconfirmed inference, or made the user feel surveilled. | Kivi’s product thesis makes trust boundaries part of correctness. | §3.1; §4 |
| Silence after non-intervention is harmless. | A visible account of what was retrieved, withheld, or rejected, including abstention. | Kivi uses legibility to calibrate trust and make correction possible. | §2.3; Appendix A labels traces as debugging output |
| Timestamp is metadata, not semantics. | Temporal truth with validity intervals, supersession, decay, and the possibility that the same statement was true at two different times. | Kivi explicitly models people and work as changing. | §2.2 “Data schema”; contradiction behavior otherwise underspecified |
| A binary task outcome adequately labels the lesson. | Separate labels for outcome, causal contribution, factuality, safety, and transfer conditions. | A successful trajectory can contain bad or irrelevant actions; a failed trajectory can contain good steps and a wrong diagnosis. | §2.1 “Processing”; Appendix A |
| Cross-actor sharing is technically universal unless performance says otherwise. | Memory isolation as a product and rights boundary even when sharing would improve metrics. | Kivi’s user-specific memory cannot be pooled merely because embeddings transfer. | §2.2 “Cold start”; §4 |
| Wrong memories are repaired by more data. | User-authored correction that removes standing and blocks re-derivation from unchanged evidence. | Kivi explicitly identifies regrowth after deletion as a critical trust failure. | No repair path in §§2–4 or Appendix A |
| Aggregate task averages are sufficient. | Per-intervention counterfactual evaluation: did this exact memory and advice improve or harm the next decision? | The current study cannot isolate helpful retrieval from extra reasoning or identify harmful advice hidden by net gains. | §4; Table 1 |

## 4. Questions the paper never faced

These arise from Kivi’s stated users, constraints, and failure modes—not from generic gaps in WebCoach.

1. **When one transcript mixes the user’s words with quoted messages, application context, and other people’s personal information, what should determine which subject each candidate memory is about?**
2. **When a fact is useful for producing the current reply but forbidden from durable storage, what structural boundary proves that it left the context window without reaching the write path?**
3. **When a work-level fact about the user’s world necessarily names another person, what distinguishes permissible relational residue (“Priya is the Acme contact”) from a retained dossier about that person?**
4. **When content falls into a sensitive category, should the system discard it even if the user explicitly states it, and what evidence of the discard may itself be safely logged?**
5. **When repeated behavior suggests a preference, what should determine whether Kivi may merely retrieve it, disclose it as an observation, or silently act on it as a rule?**
6. **When an observation appears many times but the user never confirms it, what—if anything—could increase its authority without violating “nothing self-promotes”?**
7. **When a proposed explanation of behavior is generated, should it exist durably as a question, transiently for one response, or not at all—and what event changes that status?**
8. **When the same memory is relevant in regular dictation and in a Hey Kivi request, what should determine which representation and tier each surface is structurally able to load?**
9. **When the permission dial is restrictive but retrieval finds a higher-tier memory, what trace should reveal that withholding occurred without disclosing the withheld content?**
10. **When a one-time invitation such as “what do you think?” expands permission, what determines its scope and prevents that permission from persisting into later requests or memory writes?**
11. **When a user correction conflicts with multiple old transcripts, should the correction edit content, supersede standing, reinterpret old evidence, or create a suppression—and which history remains visible?**
12. **When the user says “that’s not me anymore,” what identity should the suppression target so that the same pattern cannot regrow under paraphrase?**
13. **When “Forget” and “That’s not me anymore” both suppress re-derivation, what different provenance, visibility, or future relearning behavior should distinguish them?**
14. **When an observation has not been re-observed, what should determine decay: elapsed time, opportunity to observe, context frequency, evidence diversity, or user-defined relevance?**
15. **When two facts conflict because the world changed rather than because one source was wrong, how should Kivi represent temporal succession without presenting old truth as current error?**
16. **When Kivi lacks an answer, what evidence about its search can be shown without implying exhaustive coverage or leaking content the current permission mode withholds?**
17. **When confirmation prompts impose attention cost, what should determine which uncertain memory earns the limited prompt budget, and whose estimate of “value” governs?**
18. **When a source transcript is opened from a memory, what surrounding third-party or sensitive content must be redacted while keeping the provenance check meaningful?**
19. **When the system’s own extraction or exclusion classifier is wrong, what recourse lets the user repair the boundary without turning them into a memory administrator?**
20. **When Kivi produces a correct output for the wrong memory reason, should the response count as success, and what trace would make that failure observable?**

## 5. Evaluation gap

### What the paper measured

- End-state success on 643 live WebVoyager tasks across 15 domains, judged from the last browser state against the query (§3.1, §4, Appendix B).
- Mean action steps and mean completion time (§4, Table 1).
- Results across three open-source actor backbones, two Coach choices in frozen-memory conditions, and self-generated dynamic memory (§4).
- Retrieval latency for K=1…10 over 600 trajectories, repeated 200 times (§2.2 Fig. 2).
- Qualitative examples and trace inspection, including an Apple product task (Appendix A).
- Same-task-ID exclusion intended to reduce evaluation leakage (§3.2).

The paper does **not** report statistical uncertainty or repeated-run variance for task success; intervention rate; retrieval recall/precision; Condenser fidelity; advice correctness; memory growth curves; stale-memory behavior; privacy leakage; contradiction resolution; correction success; deletion/suppression; user-visible calibration; token or monetary cost; or tail latency.

### What the paper provides Kivi—and what it does not

The evidence supports a narrow precedent: for some medium/large web-navigation actors, a separate LLM that repeatedly receives retrieved summaries of prior completed trajectories can improve live benchmark task success, while usually reducing action count and substantially increasing elapsed time (§4, Table 1).

It provides **no comparative evidence** for Kivi’s major choices about retention eligibility, third-party boundaries, sensitive-category exclusion, epistemic tiers, retrieval/disclosure separation, user-visible provenance, contradiction and supersession, decay, correction, forgetting, suppression against re-derivation, or abstention. On those decisions, WebCoach is a precedent for an episodic coaching architecture, not evidence between Kivi’s defensible alternatives.
