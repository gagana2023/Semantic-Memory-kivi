# Decision space extracted from Nocturne Memory for Kivi

Scope: repository `Dataojitori/nocturne_memory`, checked out at the current `main`; comparison target: `../kivi-semantic-memory-position.md`. This is a map of questions and precedent, not a recommendation. “Deliberate” means the repository contains an explicit comment, schema constraint, test, migration, or documented interface supporting the choice. “Accident” means behavior follows from an implementation default without such evidence. “Unclear” means the available code and history do not establish intent.

## 0. Orientation — report before analysis

### Core, versus glue and integrations

- **Core mutation and graph invariants:** `backend/db/graph.py`. `GraphService` owns reads, child ordering, graph diagnostics, version chains, cycle prevention, alias/path cascades, soft GC, hard deletion, rollback, and orphan restoration (`backend/db/graph.py:50`, `backend/db/graph.py:95`, `backend/db/graph.py:251`, `backend/db/graph.py:968`, `backend/db/graph.py:1005`, `backend/db/graph.py:1373`, `backend/db/graph.py:1452`, `backend/db/graph.py:1709`, `backend/db/graph.py:2195`). This is the main concentration of load-bearing logic.
- **Core retrieval:** `backend/db/search.py` and `backend/db/search_terms.py`. They build a denormalized per-path document and implement SQLite FTS5/PostgreSQL full-text ranking, token expansion, alias deduplication, and result truncation (`backend/db/search.py:92`, `backend/db/search.py:224`, `backend/db/search.py:279`, `backend/db/search_terms.py:8`, `backend/db/search_terms.py:81`, `backend/db/search_terms.py:86`).
- **Core trigger/link logic:** `backend/db/glossary.py` maps literal keywords to nodes and scans active memory content (`backend/db/glossary.py:31`, `backend/db/models.py:171`).
- **Application/protocol layer:** `backend/mcp_server.py` defines the seven MCP operations, URI parsing, system views, validation, and human-readable error/result strings (`backend/mcp_server.py:190`, `backend/mcp_server.py:284`, `backend/mcp_server.py:390`, `backend/mcp_server.py:508`, `backend/mcp_server.py:733`, `backend/mcp_server.py:786`, `backend/mcp_server.py:895`, `backend/mcp_server.py:1018`). It contains substantive policy at the boundary, but persistence invariants live below it.
- **Infrastructure/glue:** `backend/db/database.py` owns engines, sessions, transactions, and migrations and explicitly says it has no business logic (`backend/db/database.py:3-9`, `backend/db/database.py:35-41`). `backend/web_app.py`, `backend/main.py`, `backend/run_sse.py`, `backend/mcp_wrapper.py`, and `backend/namespace_middleware.py` are transport/hosting compatibility layers (`backend/main.py:3-7`, `backend/mcp_wrapper.py:11`, `backend/namespace_middleware.py:1-18`).
- **Human adapter:** `backend/api/*` plus `frontend/src/*` expose browsing, settings, review, maintenance, presets, and build status; the review API contains nontrivial rollback orchestration but not the memory-selection model (`backend/api/review.py:623-626`, `backend/web_app.py:130`).
- **Examples/integrations:** `desktop_pet/*`, `scripts/import_chara_card.py`, `scripts/extract_chara_card.py`, and `docs/skills/*` are clients, import/export helpers, or operational playbooks rather than the storage engine (`desktop_pet/heartbeat_engine.py:1`, `scripts/import_chara_card.py:1`, `docs/skills/memory-audit/SKILL.md:1`).
- **Legacy, not current core:** `backend/db/neo4j_client.py` remains as migration-era code; the migration script calls it the old pre-1.0 backend (`backend/scripts/migrate_neo4j_to_sqlite.py:3-6`). Treating its decisions as current would confuse backward compatibility with present design.

### Data model and frozen decisions

- A `Node` is the stable conceptual identity; `Memory` rows are immutable-ish content versions linked by `migrated_to`; `Edge` is a unique parent→child relation carrying `name`, `priority`, and `disclosure`; `Path` is a materialized `(namespace, domain, path)` URI cache pointing to an edge/node (`backend/db/models.py:73-92`, `backend/db/models.py:95-111`, `backend/db/models.py:114-142`, `backend/db/models.py:145-168`).
- The fixed all-zero root UUID avoids SQLite’s `NULL != NULL` uniqueness behavior; this is explicitly deliberate (`backend/db/models.py:32-34`).
- `GlossaryKeyword` is a many-to-many-like literal trigger binding scoped by namespace; uniqueness is `(keyword, node_uuid, namespace)` (`backend/db/models.py:171-196`).
- `SearchDocument` duplicates URI, content, disclosure, search terms, priority, namespace, and memory ID once per reachable path; it is explicitly derived (`backend/db/models.py:199-224`).
- `MemoryAccessLog` stores node, namespace, access time, and a 64-character context label; `Node.last_accessed_at` also caches the latest access (`backend/db/models.py:82-84`, `backend/db/models.py:227-243`).
- `Preset` serializes boot URI maps and path masks as JSON strings in text columns and enforces at most one active preset with a partial unique index (`backend/db/models.py:246-271`).
- The review ledger is not relational: one locked JSON file stores first `before` and latest `after`, keyed by table primary key; net-zero changes are filtered (`backend/db/snapshot.py:2-9`, `backend/db/snapshot.py:34-40`, `backend/db/snapshot.py:128-165`). Memory content is intentionally omitted from ledger rows and resolved from retained database versions (`backend/db/models.py:58-65`, `backend/db/models.py:279-300`).
- Migrations freeze several rewrites: flat paths became Node–Memory–Edge–Path (`backend/db/migrations/003_v1.1.0_backfill_graph_data.py:11-35`); legacy path metadata was dropped (`backend/db/migrations/004_v1.1.0_drop_legacy_path_columns.py:8-23`); orphan memories were deprecated (`backend/db/migrations/006_v1.1.0_deprecate_orphan_memories.py:17-31`); one active version per node became a database constraint (`backend/db/migrations/007_v1.1.0_enforce_single_active_memory.py:8-16`); search became a derived FTS index (`backend/db/migrations/009_v1.3.0_add_search_fts.py:9-21`); namespaces and access logs arrived later (`backend/db/migrations/010_v2.0.0_add_namespace.py:1`, `backend/db/migrations/012_v2.1.0_add_access_logs.py:1`).
- Pydantic types in `backend/models/schemas.py` model diff/rollback payloads, not semantic memories; the persisted memory schema has no `type`, epistemic `tier`, evidence set, transcript provenance, confirmation time, or suppression record (`backend/models/schemas.py:5-66`, `backend/db/models.py:95-110`). That absence is directly material to Kivi’s required schema (`../kivi-semantic-memory-position.md:99`).

### Main execution path: entry point to persistence

1. `backend/mcp_server.py` constructs FastMCP with a lifespan; startup materializes config, initializes tables/migrations unless `SKIP_DB_INIT`, promotes legacy boot URIs, starts a background frontend build, and may embed the HTTP UI (`backend/mcp_server.py:69-87`, `backend/mcp_server.py:89-142`).
2. A tool call enters one of `read_memory`, `create_memory`, `update_memory`, `delete_memory`, `add_alias`, `manage_triggers`, or `search_memory` (`backend/mcp_server.py:284`, `backend/mcp_server.py:390`, `backend/mcp_server.py:508`, `backend/mcp_server.py:733`, `backend/mcp_server.py:786`, `backend/mcp_server.py:895`, `backend/mcp_server.py:1018`). URI parsing selects domain/path and request context supplies the namespace (`backend/mcp_server.py:190-229`, `backend/namespace_middleware.py:11-18`).
3. Reads intercept `system://*` commands or call `fetch_and_format_memory`; ordinary reads resolve a materialized path to its active memory and ordered children, then log access (`backend/mcp_server.py:310-382`, `backend/system_views.py:21-164`, `backend/db/graph.py:95-160`, `backend/db/graph.py:251-361`).
4. Writes validate protocol arguments and call `GraphService`; each service operation uses an async SQLAlchemy session whose context manager commits on success and rolls back on exception (`backend/mcp_server.py:457-480`, `backend/db/graph.py:1373-1450`, `backend/db/database.py:105-114`).
5. Content update inserts a new initially-deprecated version, points active versions to it, activates it, and refreshes every namespace’s derived search documents for that node (`backend/db/graph.py:1520-1549`). Path and alias operations also cascade materialized paths and refresh affected search documents (`backend/db/graph.py:1602-1708`, `backend/db/graph.py:1709-1956`).
6. The MCP wrapper records returned `rows_before`/`rows_after` into the single changeset pool for later human integration or rollback (`backend/mcp_server.py:248-280`, `backend/db/snapshot.py:128-208`).

## 1. Decision inventory

Each item is a question with at least two defensible answers. “Kivi push” describes how the differing premise changes the pressure; it does not select an answer.

### 1.1 What enters the write path: explicit agent-authored memories, or automatic extraction from interaction evidence?

- **Repo answer:** only explicit MCP calls create/update memory; `create_memory` requires parent URI, content, priority, disclosure, and title, while no transcript-ingestion or candidate-extraction API exists (`backend/mcp_server.py:390-456`). The README states that there is no background automatic summarizer and the AI decides what to create and maintain (`README_EN.md:108-117`).
- **Placement/confidence:** deliberate and hardcoded at the product boundary; there is no extractor plug-in interface (`backend/mcp_server.py:390-456`).
- **Assumptions:** an agent is both observer and memory author, and the cost of explicit tool use is acceptable (inferred from the required write tools and absence of an ingestion path).
- **Kivi push:** Kivi explicitly starts from transcripts/application context and demands candidate filtering before storage (`../kivi-semantic-memory-position.md:7`, `../kivi-semantic-memory-position.md:47-49`). The difference pushes this question from “agent autonomy” toward “controlled extraction,” without deciding the extractor architecture.

### 1.2 Is a memory primarily free text in an addressable graph, or a typed epistemic claim with evidence?

- **Repo answer:** a memory is `content` plus graph placement metadata; the schema has no semantic type/tier/evidence/provenance/status fields (`backend/db/models.py:95-110`, `backend/db/models.py:114-168`).
- **Placement/confidence:** deliberate graph separation is schema-level and migration-backed; omission of epistemic fields is an unexamined default or out-of-scope choice—intent is **unclear** (`backend/db/models.py:3-11`, `backend/db/migrations/003_v1.1.0_backfill_graph_data.py:11-35`).
- **Assumptions:** hierarchy, aliasing, and author-written prose carry enough meaning for retrieval (inferred from `Path`, `Edge`, and full-text document composition at `backend/db/search.py:343-363`).
- **Kivi push:** Kivi requires independent type and tier axes plus evidence/source/time/status (`../kivi-semantic-memory-position.md:71-99`), so Nocturne is precedent for routing/version identity, not evidence for Kivi’s belief schema.

### 1.3 Should third-party and sensitive material be structurally blocked, filtered after extraction, or left to the writer?

- **Repo answer:** unrestricted text enters `Memory.content`; the write validation checks priority/disclosure/title and edit shape, not subject or person (`backend/db/models.py:104-109`, `backend/mcp_server.py:457-480`, `backend/mcp_server.py:562-700`).
- **Placement/confidence:** likely scope omission rather than affirmative privacy design; **unclear**. No exclusion/suppression table or dropped-candidate log exists in the models (`backend/db/models.py:73-271`).
- **Assumptions:** the writing agent/user supplies appropriate content and bears classification responsibility (inference).
- **Kivi push:** Kivi commits to a pre-storage sensitive-category check and a structural third-party barrier with visible drop reasons (`../kivi-semantic-memory-position.md:47-49`, `../kivi-semantic-memory-position.md:112-125`). This is a question Nocturne did not face.

### 1.4 Is the stable identity the claim, its location, or an underlying concept independent of both?

- **Repo answer:** stable identity is a UUID `Node`; content versions and paths can change around it (`backend/db/models.py:73-100`).
- **Placement/confidence:** high-confidence, schema-level, deliberately documented, and reinforced throughout update/alias behavior (`backend/db/models.py:74-78`, `backend/db/graph.py:1520-1549`, `backend/db/graph.py:1602-1708`).
- **Assumptions:** users/agents can recognize one conceptual node across edits and aliases; identity mistakes are costly enough to preserve separately (inference from version/alias design).
- **Kivi push:** this can represent a revisable belief identity, but Kivi also needs source-level identity and correction/suppression events (`../kivi-semantic-memory-position.md:23`, `../kivi-semantic-memory-position.md:240-242`). The difference pushes toward asking whether “same concept” and “same proposition about the user” are equivalent.

### 1.5 On update, overwrite in place or append a version and supersede the old one?

- **Repo answer:** append a new `Memory`, deprecate all active versions, link them via `migrated_to`, then activate the new row (`backend/db/graph.py:1520-1544`). At most one active row is enforced at the database level; migration repair keeps latest by `created_at DESC, id DESC` (`backend/db/migrations/007_v1.1.0_enforce_single_active_memory.py:11-16`).
- **Placement/confidence:** high-confidence and deliberate: schema, migration, service logic, rollback, and tests agree (`backend/db/models.py:98-109`, `backend/db/graph.py:1562-1600`, `backend/tests/service/test_graph_service.py:4-29`).
- **Assumptions:** storage cost of old full text is acceptable; revision is linear; “latest” resolves accidental duplicate active rows (inference plus migration rule).
- **Kivi push:** Kivi also requires supersession history (`../kivi-semantic-memory-position.md:240`), but contradiction between sourced claims may be different from editing one author-owned document. This pushes the question toward whether a linear chain preserves enough evidence semantics.

### 1.6 What happens on duplicate path, duplicate relation, or duplicate content?

- **Repo answer:** duplicate `(namespace,domain,path)` is rejected by the path primary key; duplicate parent→child relation is prevented by a unique constraint; aliases intentionally point multiple paths to the same node; similar content in different memory IDs is only described as redundant, not automatically merged (`backend/db/models.py:132-134`, `backend/db/models.py:145-158`, `backend/mcp_server.py:297`, `backend/mcp_server.py:786-810`).
- **Placement/confidence:** path/relation handling is database-hardcoded and deliberate; semantic duplicate handling is manual/incomplete because diagnostics can report duplicate aliases but no content deduper exists (`backend/db/graph.py:612`, `backend/system_views.py:497-509`).
- **Assumptions:** exact identity collisions matter; semantic duplication is rare or requires human/agent judgment (inference).
- **Kivi push:** repeated evidence must often increment evidence rather than create a duplicate, while contradictory evidence may supersede (`../kivi-semantic-memory-position.md:99`, `../kivi-semantic-memory-position.md:240`). The difference creates a separate identity-resolution question before URI conflict handling.

### 1.7 If deleting a path would orphan descendants, reject, cascade-delete, or auto-heal?

- **Repo answer:** preserve content where possible; removal may rehome descendant paths under a surviving alias, disambiguate collisions with UUID suffixes, or reject when no safe route exists (`backend/db/graph.py:1709-1834`). A node with no path is soft-GCed by deprecating its memory rather than erasing it (`backend/db/graph.py:1306-1360`).
- **Placement/confidence:** deliberate but evolved; service logic and multiple tests cover rejection, healing, collision, and soft GC (`backend/tests/service/test_graph_service.py:64-82`, `backend/tests/service/test_graph_service.py:129-224`).
- **Assumptions:** recoverability outranks stable URI aesthetics; path deletion is not equivalent to forgetting content (inference from soft GC).
- **Kivi push:** Kivi’s “Forget” explicitly removes and suppresses re-derivation (`../kivi-semantic-memory-position.md:241-249`). The difference pushes toward separating topology edits, belief demotion, source deletion, and durable suppression.

### 1.8 Who resolves contradictions: last write, explicit correction, accumulation, or user confirmation?

- **Repo answer:** `update_memory` creates a newest active version; migration cleanup selects latest timestamp/ID when multiple active versions exist (`backend/db/graph.py:1520-1544`, `backend/db/migrations/007_v1.1.0_enforce_single_active_memory.py:13-16`). The store does not identify semantic contradiction.
- **Placement/confidence:** version conflict behavior is deliberate; semantic contradiction policy is absent, so **unclear** (`backend/db/models.py:95-110`).
- **Assumptions:** the caller already knows which URI/concept to correct and provides authoritative replacement text (inference from URI-targeted update).
- **Kivi push:** Kivi distinguishes stated, observed, and hypothesized claims and requires explicit confirmation for promotion (`../kivi-semantic-memory-position.md:77-95`). That makes authority and evidence freshness part of conflict resolution, not merely recency.

### 1.9 Retrieve by explicit address, lexical relevance, graph neighborhood, semantic similarity, or all of them?

- **Repo answer:** explicit URI reads traverse direct children; search is lexical FTS over path, URI, content, disclosure, and glossary-derived terms; there are no embeddings (`backend/db/graph.py:251-361`, `backend/db/search.py:279-391`, `backend/db/migrations/009_v1.3.0_add_search_fts.py:16-21`). Glossary triggers add literal cross-links (`backend/db/glossary.py:31`, `backend/db/models.py:171-178`).
- **Placement/confidence:** deliberate and pluggable only at the database-dialect implementation level; retrieval strategy itself has no provider interface (`backend/db/search.py:294-370`).
- **Assumptions:** memory is sufficiently organized and named for lexical/addressable access; explainable routing is preferred over embedding recall (inference, consistent with README’s rejection of vector retrieval at `README_EN.md:77-94`).
- **Kivi push:** Kivi deliberately leaves embeddings/structured/hybrid open (`../kivi-semantic-memory-position.md:267-273`). Its absent-answer and evidence-distributed claims raise recall/calibration questions Nocturne’s exact-address interface does not answer (`../kivi-semantic-memory-position.md:205-228`, `../kivi-semantic-memory-position.md:281-286`).

### 1.10 How are results ordered, and where does priority enter?

- **Repo answer:** children order by lower edge priority then name; search orders by FTS score, then lower priority, then shorter path; duplicate aliases collapse to the first encountered node (`backend/db/graph.py:280`, `backend/db/search.py:320-321`, `backend/db/search.py:365-390`). Random resurfacing weights staleness multiplied by `0.5^priority` (`backend/db/graph.py:715-763`).
- **Placement/confidence:** priority is caller-configurable per edge, while ranking formula/tie-breaks are hardcoded. This reveals confidence in priority as a concept but lower confidence delegated to the author about its value (`backend/db/models.py:117-129`, `backend/mcp_server.py:424-433`).
- **Assumptions:** lower integers consistently mean more important; graph placement can have different recall importance through aliases (`backend/mcp_server.py:793-810`).
- **Kivi push:** Kivi’s permission tier is not importance and the dial governs disclosure after retrieval (`../kivi-semantic-memory-position.md:155`). The difference pushes toward separate relevance, epistemic confidence, disclosure permission, freshness, and user-value ordering axes.

### 1.11 Is disclosure a machine-enforced permission or a human-readable hint to the caller?

- **Repo answer:** `disclosure` is free text on an edge, included in formatted reads/search results; no policy engine interprets it (`backend/db/models.py:127-130`, `backend/db/search.py:379-388`, `backend/mcp_server.py:401-403`).
- **Placement/confidence:** field is schema-level and required at MCP create time, but enforcement is delegated to the consuming model; this is deliberate metadata with non-enforced semantics (`backend/mcp_server.py:460-464`).
- **Assumptions:** an LLM can read and obey natural-language trigger conditions reliably enough (inference).
- **Kivi push:** Kivi requires a two-position persistent permission plus one-request escalation and explicit withheld traces (`../kivi-semantic-memory-position.md:128-172`). The difference pushes from advisory disclosure text toward enforceable tier gating, without selecting where enforcement belongs.

### 1.12 What is exposed to callers: raw content, metadata, graph context, evidence, or an explanation trace?

- **Repo answer:** a read returns content, memory ID, priority, disclosure, aliases/children, and glossary references; search returns URI, snippet, priority, disclosure (`backend/mcp_server.py:297-303`, `backend/system_views.py:21-164`, `backend/mcp_server.py:1048-1066`). It does not expose source transcripts, extraction decisions, withheld candidates, or evidence counts because they are not stored (`backend/db/models.py:95-110`).
- **Placement/confidence:** output is hardcoded protocol formatting; no response-schema plug-in exists (`backend/system_views.py:21-164`).
- **Assumptions:** author-written memory is itself the provenance and explanation (inference).
- **Kivi push:** Kivi requires a Why panel with retrieved/withheld/used/source evidence, including for abstention (`../kivi-semantic-memory-position.md:227-228`).

### 1.13 On missing data or low confidence, return an error/empty set, ask, abstain with trace, or guess?

- **Repo answer:** missing URI and invalid input become text beginning `Error:`; empty search returns “No memories found”; the storage system has no confidence score and cannot distinguish absent evidence from low-confidence belief (`backend/mcp_server.py:381-386`, `backend/mcp_server.py:1048-1054`, `backend/db/models.py:95-110`).
- **Placement/confidence:** error behavior is deliberate at the MCP boundary; low-confidence behavior is not represented, so **unclear**.
- **Assumptions:** the caller model performs conversational recovery (inference).
- **Kivi push:** abstention is a product result that must state what was searched, and hypotheses remain questions (`../kivi-semantic-memory-position.md:205-228`, `../kivi-semantic-memory-position.md:92-95`).

### 1.14 What changes over time automatically?

- **Repo answer:** access timestamps/logs change on reads; diagnostic staleness changes with time; no content decays, expires, promotes, or demotes automatically (`backend/db/graph.py:76-93`, `backend/db/models.py:227-243`, `backend/db/graph.py:438-524`, `backend/db/models.py:95-110`). Random resurfacing makes older items more likely (`backend/db/graph.py:715-763`).
- **Placement/confidence:** access logging and diagnostics are deliberate; absence of semantic decay is **unclear** rather than proven opposition.
- **Assumptions:** maintenance is periodic and agent/human-driven, not lifecycle automation (inference from diagnostics and maintenance tools).
- **Kivi push:** observations decay and hypotheses expire, while stated claims do not self-promote (`../kivi-semantic-memory-position.md:95`, `../kivi-semantic-memory-position.md:238-242`).

### 1.15 What is assumed idempotent or ordered?

- **Repo answer:** create is not idempotent: an occupied path errors; update of an already-active rollback target reports `was_already_active`; snapshot recording is order-sensitive—first `before` is frozen and later `after` overwrites; transactions serialize each service call but no request id/idempotency key exists (`backend/db/graph.py:1373-1450`, `backend/db/graph.py:1575-1579`, `backend/db/snapshot.py:4-7`, `backend/db/snapshot.py:145-165`, `backend/db/database.py:105-114`).
- **Placement/confidence:** snapshot ordering is explicit and tested; network/tool retry semantics are an unexamined default (`backend/tests/unit/test_snapshot.py:4-23`).
- **Assumptions:** MCP client will not blindly retry successful writes after losing the response; writes concerning one concept arrive in intended order (inference).
- **Kivi push:** transcript replay and reprocessing make idempotent extraction essential, and “did not regrow on reprocessing” is an explicit evaluation claim (`../kivi-semantic-memory-position.md:241`, `../kivi-semantic-memory-position.md:286`).

### 1.16 Is multi-user separation a namespace column, separate database, or authorization boundary?

- **Repo answer:** namespace scopes paths, glossary, search, access logs, and presets, while nodes/memories/edges are shared underlying identities (`backend/db/models.py:145-168`, `backend/db/models.py:171-224`, `backend/db/models.py:227-260`). Middleware obtains namespace from environment/header/query transport (`backend/namespace_middleware.py:11-18`).
- **Placement/confidence:** added later and heavily tested for behavioral isolation (`backend/tests/service/test_namespace_isolation.py:66-639`), but namespace is not itself an authenticated tenant identity; authorization boundaries are **unclear** (`backend/auth.py:38-117`).
- **Assumptions:** isolation is between agents in one trusted installation, not hostile tenants (inference).
- **Kivi push:** Kivi is about one person’s revisable self-related memory and third parties who did not consent (`../kivi-semantic-memory-position.md:21-25`, `../kivi-semantic-memory-position.md:112-125`); subject/owner/source separation is a different axis from agent namespace.

## 3. What the history says

### Reversals and rewrites

- **Highest-value reversal:** the backend moved from Neo4j to SQLite/SQLAlchemy. The repository retains an explicitly “old Neo4j backend (pre-1.0)” migration script (`backend/scripts/migrate_neo4j_to_sqlite.py:3-10`), while current `DatabaseManager` supports SQLite/PostgreSQL (`backend/db/database.py:3-10`). This says the original graph-database answer stopped fitting deployment/operational needs; the stated reason is not preserved in a nearby comment, so finer intent is **unclear**.
- **High-value rewrite:** flat path records became a four-entity graph with materialized paths. Migration 003 backfills nodes/edges from legacy flat data, and migration 004 removes `memory_id`, `priority`, and `disclosure` from paths (`backend/db/migrations/003_v1.1.0_backfill_graph_data.py:11-35`, `backend/db/migrations/004_v1.1.0_drop_legacy_path_columns.py:8-23`). This is a reversal from “path owns memory/metadata” to “edge owns relational metadata and node owns conceptual identity.”
- Search changed from SQL `LIKE` to full-text search after issue #18 and merged PR #19 (<https://github.com/Dataojitori/nocturne_memory/issues/18>, <https://github.com/Dataojitori/nocturne_memory/pull/19>). The current migration explicitly creates/backfills dialect-specific FTS (`backend/db/migrations/009_v1.3.0_add_search_fts.py:9-21`, `backend/db/migrations/009_v1.3.0_add_search_fts.py:70-99`). This is a high-value reversal because retrieval mechanics were replaced, not merely extended.
- Snapshot handling was rewritten from separate snapshot types to a row-level changeset pool; current first-before/latest-after semantics are explicit (`backend/db/snapshot.py:2-9`). Git history attributes the rewrite to commits `d6de6df` and `0af8e33`; the current tests freeze overwrite and net-zero GC behavior (`backend/tests/unit/test_snapshot.py:4-43`).
- Patch matching first removed partial matching (`c396866`), later added normalized matching (`385ff64`), then block matching (`6ef21b3`). Current code prioritizes exact match, then block/normalized fallbacks and rejects ambiguity (`backend/mcp_server.py:606-660`). This repeated rewrite is high-value evidence that text-edit conflict semantics were unstable.
- `importance` was renamed to `priority` (`e056669`), and metadata migrated from Path to Edge (`backend/db/migrations/004_v1.1.0_drop_legacy_path_columns.py:8-23`). This is partly terminology and partly a real ownership reversal: metadata became relationship-specific rather than URI-row-specific.
- Namespace isolation was added later across a sequence of commits (`8266754`, `45d1c2c`, `25254e2`, `d86e6f1`, `8bc31fb`, `d705498`, `4c6c848`) and migrations 010/011 (`backend/db/migrations/010_v2.0.0_add_namespace.py:1`, `backend/db/migrations/011_v2.0.0_add_namespace_to_glossary.py:1`). The breadth implies single-agent/global state stopped working for actual deployments.
- PostgreSQL was added later via merged PR #3 for multi-device sharing (<https://github.com/Dataojitori/nocturne_memory/pull/3>); current code branches on dialect, pools PostgreSQL, and configures SQLite separately (`backend/db/database.py:44-89`).

### Shortcuts and admitted compromises

- Diagnostics fetch all reachable nodes and filter staleness in Python “to handle the MAX logic easily,” an explicit simplicity-over-scale shortcut (`backend/db/graph.py:455-471`).
- Transport security disables DNS rebinding protection with the assumption of a trusted reverse proxy (`backend/mcp_server.py:145-147`). This is deliberate deployment coupling, not a data-model choice.
- Namespace transport for legacy SSE uses a file-backed session mapping because the POST cannot otherwise carry namespace context (`backend/namespace_middleware.py:7-18`). This is backward-compatibility glue.
- Snapshot loading rewrites keys lacking namespace for backward compatibility (`backend/db/snapshot.py:91-115`).
- `PORT` is retained only as historical fallback while `WEB_PORT` is canonical (`backend/config.py:188-191`).
- Config migrates `.env` one way and then ignores it, explicitly prioritizing a single mutable config source over conventional environment override semantics (`backend/config.py:4-14`).
- No `TODO` or `FIXME` marker was found in current non-lock source by repository-wide search; that absence does not mean work is complete. Open issues #25, #32, #42, #53, and #55 show acknowledged gaps outside inline markers (<https://github.com/Dataojitori/nocturne_memory/issues/25>, <https://github.com/Dataojitori/nocturne_memory/issues/32>, <https://github.com/Dataojitori/nocturne_memory/issues/42>, <https://github.com/Dataojitori/nocturne_memory/issues/53>).

## 4. Unexamined defaults

- **One natural-language text blob per version.** No content schema, claim granularity, language tag, sensitivity tag, or provenance exists (`backend/db/models.py:95-110`). Alternative not tried in current schema: atomic typed claims with normalized evidence edges.
- **Naive local timestamps.** `datetime.now` is used without timezone on nodes, memories, edges, access logs, and presets (`backend/db/models.py:83`, `backend/db/models.py:109`, `backend/db/models.py:130`, `backend/db/models.py:240`, `backend/db/models.py:260-261`). Alternative not tried: UTC-aware timestamps/database-generated time.
- **Last-write-as-current.** Active-version repair uses latest timestamp then ID (`backend/db/migrations/007_v1.1.0_enforce_single_active_memory.py:13-16`). Alternative not tried: source authority, explicit conflict state, or user-confirmed resolution.
- **Linear version pointer without a foreign key.** `migrated_to` is an unconstrained integer (`backend/db/models.py:108`). Alternative not tried: self-referential FK plus cycle/branch constraints or an explicit event table.
- **Natural-language disclosure without enforcement.** It is text on `Edge` and returned to the model (`backend/db/models.py:127-130`, `backend/db/search.py:379-388`). Alternative not tried: enumerated policy plus deterministic gate.
- **Keyword/full-text retrieval equals “memory search.”** Search documents concatenate all fields under a simple tokenizer (`backend/db/search.py:343-363`, `backend/db/migrations/009_v1.3.0_add_search_fts.py:95`). Alternative not tried: embedding, graph spreading, recency fusion, evidence-aware retrieval, or hybrid reranking.
- **SQLite and PostgreSQL are behaviorally equivalent enough.** They use different ranking functions/order polarity and tokenization (`backend/db/search.py:294-365`). Alternative not tried: a normalized relevance contract with cross-dialect ranking tests.
- **Per-path search duplication.** Every alias becomes a document, then results deduplicate by node after over-fetch (`backend/db/models.py:199-224`, `backend/db/search.py:372-390`). Alternative not tried: one node document plus a separate path feature/index.
- **Namespace is an empty string by default.** It is repeated as schema and API default (`backend/db/models.py:155`, `backend/db/models.py:189`, `backend/db/models.py:204`, `backend/db/graph.py:95`). Alternative not tried: explicit mandatory tenant/subject IDs.
- **Human review batches all AI changes into one global file.** One `changeset.json` accumulates first-before/latest-after (`backend/db/snapshot.py:2-9`). Alternative not tried: append-only transaction/event records per request, actor, namespace, or transcript.
- **Memory content stays in the DB so snapshots can omit it.** Review resolves retained versions later (`backend/db/models.py:58-65`, `backend/db/models.py:286-288`). Alternative not tried: immutable event payloads that survive hard deletion.
- **Errors are successful tool text, not typed error objects.** Exceptions are caught and formatted as `Error: ...` (`backend/mcp_server.py:381-386`, `backend/mcp_server.py:1042-1070`). Alternative not tried: structured error codes/retryability/conflict metadata.
- **No request id or idempotency key.** Write signatures contain content/path metadata only (`backend/mcp_server.py:390-456`, `backend/mcp_server.py:508-575`). Alternative not tried: caller-supplied operation IDs or source-derived deterministic keys.
- **Priority has no upper bound.** Only negative values are rejected (`backend/mcp_server.py:457-458`, `backend/mcp_server.py:562-563`). Alternative not tried: finite enum, bounded score, or learned rank.
- **Framework defaults:** SQLAlchemy engine echo is false, sessions do not expire on commit, PostgreSQL pre-ping is true, SQLite uses WAL and synchronous NORMAL (`backend/db/database.py:53`, `backend/db/database.py:74-75`, `backend/db/database.py:82-94`). Only WAL/busy-timeout has clear issue/PR provenance; deliberation for the others is **unclear**.

15. What evaluation distinguishes harmless work residue about another person from prohibited characterization of that person? Nocturne does not model subject-of-claim (`backend/db/models.py:95-110`); Kivi’s worked example makes this boundary central (`../kivi-semantic-memory-position.md:112-125`).
16. What latency/cost envelope applies to extraction, filtering, retrieval, gating, and explanation? Nocturne exposes no model calls and Kivi explicitly leaves targets open (`backend/requirements.txt:1-30`, `../kivi-semantic-memory-position.md:275`).

## 6. What the tests do not cover

A different answer to each question below could still pass the inspected suite; therefore the repository supplies precedent, not evidence.

- **Sensitive/third-party retention:** no test feeds a mixed user/third-party transcript or asserts a drop reason because there is no extraction path (`backend/tests/conftest.py:1-80`, `backend/db/models.py:73-271`).
- **Epistemic tier correctness:** no test distinguishes stated from observed/hypothesized, confirmation from silence, or fact from question; fields do not exist (`backend/db/models.py:95-110`).
- **Provenance:** no test requires source transcript IDs, evidence counts, first-seen/last-confirmed times, or one-tap source recovery (`backend/db/models.py:95-110`).
- **Disclosure enforcement:** tests carry/display disclosure, but no test proves a caller cannot receive disallowed content (`backend/tests/mcp/test_mcp_tools.py:54-238`, `backend/db/search.py:379-388`). A repository-wide test-name inventory contains no permission-tier/withheld test (absence inferred from `backend/tests/**`).
- **Abstention quality:** empty search and missing URI behavior are exercised only as tool responses, not for truthful natural-language near-miss explanation (`backend/tests/mcp/test_mcp_tools.py:54-238`, `backend/mcp_server.py:1048-1054`).
- **Semantic contradiction/duplicate detection:** tests cover exact paths, aliases, and version chains, not two differently worded incompatible claims (`backend/tests/service/test_graph_service.py:4-243`).
- **Retry idempotency and lost responses:** no write API accepts an operation ID, and tests do not repeat the same create after simulated commit/response loss (`backend/mcp_server.py:390-507`, `backend/tests/mcp/test_mcp_tools.py:54-238`).
- **Concurrent writes to the same node/path:** tests are async but sequential at the behavior level; no barrier/race fixture distinguishes optimistic locking, last-write-wins, or unique-constraint failure (`backend/tests/service/test_graph_service.py:4-243`).
- **Search relevance:** the search test asserts refresh after content/alias changes, not an evaluation set for ranking, dialect parity, recall, or BM25 weights (`backend/tests/service/test_search_indexer.py:1`). A different ranking formula could pass.
- **Alias-heavy truncation:** no test establishes that `max(limit*5,50)` returns `limit` unique nodes under extreme alias skew (`backend/db/search.py:284-390`).
- **Staleness/crowding/random formulas:** no test file is named for diagnostics or random weighting, and service tests do not assert formula boundaries (`backend/tests/service/test_graph_service.py:4-243`; absence inferred from test inventory). All cited magic-number alternatives could pass.
- **Long migration chains/cycles:** hard-delete chain repair is tested for a short chain, not `50+` versions or a corrupted cycle (`backend/tests/service/test_graph_service.py:226-243`, `backend/db/graph.py:2067-2100`).
- **Cross-dialect equivalence:** fixtures use temporary SQLite (`backend/tests/conftest.py:20-48`); no PostgreSQL test fixture is present. PostgreSQL ranking, partial indexes, SSL, and pooling remain unverified by this suite (`backend/db/database.py:54-78`).
- **Namespace as a security boundary:** isolation tests prove query scoping, not authentication/authorization against namespace spoofing (`backend/tests/service/test_namespace_isolation.py:66-639`, `backend/namespace_middleware.py:11-18`).
- **Snapshot durability across crash/process races:** unit tests cover overwrite, GC, and legacy keys, not torn JSON writes, disk-full, process death, or DB-commit/ledger-write split brain (`backend/tests/unit/test_snapshot.py:4-73`, `backend/db/snapshot.py:119-122`).
- **Hard deletion versus auditability:** tests verify chain repair but not whether later review can reconstruct content after permanent purge (`backend/tests/service/test_graph_service.py:226-243`, `backend/db/models.py:58-65`).
- **Open glossary-cascade report:** the current suite’s glossary test covers explicit scan/remove, not all node deletion paths that issue #42 says leave dangling triggers (`backend/tests/service/test_glossary_service.py:1`, <https://github.com/Dataojitori/nocturne_memory/issues/42>).
- **UI legibility and reversibility:** backend review rollback is tested, but the main browser/review components have no corresponding tests in the repository; only localization and maintenance-section tests exist (`frontend/src/i18n/i18n.test.js:1`, `frontend/src/features/settings/MaintenanceSection.test.jsx:1`; absence inferred from file inventory).
- **MCP conformance:** repository tests call Python tool functions rather than an external protocol conformance matrix (`backend/tests/mcp/test_mcp_tools.py:1-568`). Closed issues #57/#58 reported version-negotiation/discovery failures, so passing internal tests would not establish protocol compliance (<https://github.com/Dataojitori/nocturne_memory/issues/57>, <https://github.com/Dataojitori/nocturne_memory/issues/58>).
- **Kivi’s seven demonstration claims:** none of exclusion/drop logging, third-party non-retention, multi-transcript evidence assembly, tier-based withholding, traceful abstention, correction suppression, or structurally restricted dictation retrieval exists in the Nocturne tests (`../kivi-semantic-memory-position.md:277-286`; comparison against `backend/tests/**` is an inference from the complete test inventory).

## Boundary statement

The strongest transferable evidence in this repository concerns stable concept identity, append-only content versions, graph/path separation, alias-aware mutation, recoverability, namespace scoping, and the operational hazards revealed by their later rewrites (`backend/db/models.py:73-168`, `backend/db/graph.py:1373-1956`, `backend/db/migrations/003_v1.1.0_backfill_graph_data.py:11-35`). It supplies almost no evidence for Kivi’s defining decisions—subject privacy, extraction-time exclusion, evidence provenance, epistemic tiers, disclosure enforcement, decay/expiry, confirmation budgeting, suppression, and traceful abstention—because those questions are absent from its schema and tests (`backend/db/models.py:73-271`, `../kivi-semantic-memory-position.md:21-25`, `../kivi-semantic-memory-position.md:47-49`, `../kivi-semantic-memory-position.md:99`, `../kivi-semantic-memory-position.md:205-249`). That is a scope mismatch, not a defect finding.
