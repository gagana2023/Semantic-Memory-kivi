# Inverting *Memory Sandbox* for Kivi

**Paper:** Ziheng Huang et al., “Memory Sandbox: Transparent and Interactive Memory Management for Conversational Agents,” arXiv:2308.01542v1 (2023). [PDF](https://arxiv.org/pdf/2308.01542)

**Target setting:** Kivi, as specified in *The Things Kivi Comes to Know*: a text-client semantic-memory system for a single user’s work context. Kivi separates retrieval from disclosure; excludes sensitive inferences and third-party personal content from the write path; distinguishes entity, preference, and episode memories and stated, observed, and hypothesised epistemic tiers; gives dictation and “Hey Kivi” different memory rights; requires provenance, abstention, correction, decay, supersession, and suppression against re-derivation.

## Reading limits

This paper is a three-page system paper/design probe. It describes an interface implemented in Next.js with GPT-3.5 Turbo, but provides no user study, benchmark, ablation, latency/cost results, error analysis, or detailed backend specification. Consequently, many pipeline decisions are **underspecified**. “Not considered” below means the paper does not discuss the alternative; it does not establish that the authors explicitly rejected it.

## 2. Forced choices

These are the decisions for which changing the paper’s answer would materially change what *Memory Sandbox* is, what its interface demonstrates, or whether its claims carry over to Kivi.

| Decision | Why load-bearing in the paper | Why it remains a real fork for Kivi |
|---|---|---|
| **D1 — user control versus automatic management** | Turning hidden memory management into direct manipulation is the central contribution. Remove this and the paper becomes an ordinary memory backend. | Kivi promises legibility but also low user burden. The unresolved fork is how much control is direct, when it appears, and which operations are system-initiated. |
| **D2 — canonical memory unit** | Every affordance assumes memory can be objectified into a manipulable unit. | Kivi must decide whether the canonical thing is a claim, episode, entity relation, preference, source fragment, or derived view. That choice controls provenance, conflict, decay, and retrieval. |
| **D3 — shared representation fidelity** | The authors’ transparency claim depends on users seeing what the model sees. | Kivi’s staged pipeline makes literal identity implausible; it must define what correspondence between stored belief, retrieved context, disclosed memory, and generated output is strong enough to deserve “transparent.” |
| **D4 — visibility as access control** | Toggling object visibility is a headline interaction. | Kivi explicitly separates retrieval from disclosure and has surface-specific access rights. Conflating the stages would undo its calibration model. |
| **D6/D7 — overwrite/delete versus history/suppression** | Edit and delete make breakdown repair tangible in the probe. | Kivi’s reversibility claim fails if correction destroys provenance or deletion allows re-derivation. |
| **D9/D10 — abstractive summarization and lineage** | Summarizing selected objects is the paper’s answer to context compression. | Kivi needs distributed evidence, typed beliefs, and auditable sources; lossy summaries may be views or may become canonical, with materially different failure modes. |
| **D11/D12 — cross-context sharing semantics** | Dragging memories between agents is the multi-agent design probe. | Kivi needs consistent state across dictation and Hey Kivi while preserving least privilege and correction propagation. Reference, copy, and re-retrieval imply different behavior. |
| **D13 — epistemic status** | The paper silently collapses history, summary, and remembered context. | Kivi’s stated/observed/hypothesised distinction determines what can be asserted or acted upon; collapsing it changes product behavior, trust, and evaluation. |
| **D14/D15/D16 — write-path eligibility** | The paper begins after content has effectively become an object, so changing this would broaden it from an interaction probe to a governed memory system. | Kivi’s strongest trust claims—sensitive exclusion and non-retention of others—live here. Post-storage deletion is not equivalent. |
| **D17 — contradiction policy** | Not required to demonstrate the short prototype, but required for any longitudinal reading of its “refine/update” claim. | Kivi commits to supersession and growth over time; conflict policy determines which belief acts as truth. |
| **D18 — retrieval/ranking** | Manual visibility and ordering substitute for a detailed retriever in the prototype. | Kivi’s value depends on finding the right work memory without making the user stage the prompt. Different retrieval choices will materially change recall, latency, and privacy exposure. |
| **D19 — transparency granularity** | The paper equates model-visible context with the explanation surface. | Kivi needs retrieved/withheld/used/source distinctions to prove its permission dial and abstention behavior. |
| **D20 — failure behavior** | Outside the paper’s implementation account. | Kivi explicitly forbids plausible guesses and makes abstention a product feature; this changes both response generation and evaluation. |
| **D22 — temporal lifecycle** | The probe can work without time-aware memory. | Kivi’s “people change” premise depends on decay, expiry, supersession, and suppression. Different lifecycle choices materially change whether old behavior cages the user. |

## 3. Unexamined defaults

These choices appear inherited or adopted without the paper framing them as open design decisions.

| Unexamined default | Where it appears | Alternative this paper/line of work does not explore here |
|---|---|---|
| **Conversation text is the raw material and natural boundary of memory.** | Memory objects are “pieces of conversational history”; summaries represent prior conversation. | Treat conversational text as evidence only, while the durable unit is a typed, contestable claim or event with explicit subject, scope, and provenance. |
| **Prompt inclusion is an adequate model of “what the model sees.”** | The shared representation equates visible front-end objects with LLM back-end context. | Distinguish availability, retrieval, prompt inclusion, model use, output disclosure, and causal influence; expose only claims the system can actually substantiate. |
| **A user can recognize harmful or inappropriate retention after storage.** | Control centers on view/edit/delete/hide. | Prevent certain material from entering durable memory at all, and expose rejected-candidate logs so policy compliance is demonstrable. |
| **Memory ownership follows the conversation/user operating the interface.** | Memory can be shared among conversations without discussion of data subjects. | Track whom each fact is about and require different retention/consent rules for the user, collaborators, clients, and bystanders. |
| **Spatial direct manipulation is a generally suitable memory-management metaphor.** | Draggable objects and multiple agents live on a 2D canvas. | Use a provenance timeline, tiered list, task-scoped trace, or queryable ledger that remains usable at thousands of memories and on narrow text surfaces. |
| **Manual curation scales far enough to be useful.** | Users toggle, order, add, edit, delete, select for summary, and drag-share objects. | Let policies and retrieval do routine work; reserve user attention for high-value uncertainty, correction, and boundary decisions. |
| **Abstractive summarization is the default compression operator.** | Selected objects are summarized by the LLM. | Structured consolidation that preserves atomic claims and evidence; extractive condensation; reversible hierarchical indexing; deliberate forgetting. |
| **Edit and delete are sufficient lifecycle operations.** | Curation affordances contain no supersede, demote, expire, pin, suppress, or dispute states. | Use an append-only correction/supersession ledger with active-state derivation and anti-rederivation tombstones. |
| **All memories have the same epistemic standing.** | No distinction among quoted history, generated summary, observation, inference, and confirmed fact. | Make assertion rights depend on tier and require explicit confirmation for promotion. |
| **All conversational agents have comparable memory rights.** | Objects are transferable across multiple agents on the same canvas. | Capability-based access by task/surface, including stores a component is structurally unable to query. |
| **The principal failure is conversational breakdown caused by misaligned mental models.** | Motivation in §1 and §3. | Treat privacy leakage, stale action, third-party harm, silent behavioral profiling, and irreversible propagation as distinct failures requiring different controls. |
| **The user is available, motivated, and sufficiently expert to debug context placement.** | Ordering is draggable because position affects LLM performance. | Make ordering an implementation responsibility and explain only actionable failures, not prompt-engineering mechanics. |

## 4. Questions the paper never faced, raised by Kivi

These derive from Kivi’s stated users, constraints, and failure modes rather than from omissions in the abstract.

### Write path and subject boundaries

1. When one input contains the user’s dictation and another person’s message, what should determine whether a derived work fact is about the user’s world rather than retained information about the other person?
2. When a candidate mixes allowed work content with an excluded sensitive category, should the system redact the sensitive span, generalize the whole candidate, or discard it entirely?
3. When a work-level fact reveals sensitive third-party information indirectly, should subject classification, semantic sensitivity, or foreseeable disclosure risk control retention?
4. When the extractor rejects a candidate, how much of the rejected content may the audit log retain without recreating the privacy violation the filter was meant to prevent?
5. When a user explicitly asks Kivi to remember sensitive information, should the hard exclusion remain absolute or become an informed, scoped exception? The Kivi position states a default and a hard list in different passages; the override semantics are not settled.

### Representation and epistemics

6. When a single belief is supported by several transcripts, should correction target the belief, individual evidence links, or both?
7. When an observation spans behavior in different contexts—client email versus internal notes—what should determine whether it is one pattern or several scoped preferences?
8. When a user confirms a hypothesis, does it become a stated fact, a stated preference, or merely a confirmed interpretation—and what actions may follow?
9. When the user states a preference once but repeatedly behaves otherwise, should the stated rule continue to govern action, be surfaced as a conflict, or become context-specific?
10. When an entity changes roles or organizations, should identity remain continuous while relations supersede, or should the system create a new scoped entity state?

### Retrieval, permission, and disclosure

11. When Kivi retrieves everything but may disclose only some of it, may withheld content still influence wording, tool choice, ranking, or abstention—or must it be causally isolated from generation?
12. When an Anbu response is improved by an observed pattern without stating the pattern, does that count as impermissible use or permissible silent personalization?
13. When the “Kivi noticed something” affordance is shown, how can the interface signal existence without leaking the sensitive gist of what was withheld?
14. When a request begins as ordinary dictation but turns into an instruction or question, what event changes the active memory rights?
15. When lexical/entity memory used for dictation contains a contested or stale name, should transcription favor the memory, the acoustic/text evidence, or ask for clarification?
16. When relevant stated memories conflict, what ranking dimensions—recency, source directness, task scope, pinning, or confirmation time—may decide which enters the response?

### Correction, time, and non-regrowth

17. When “That’s not me anymore” suppresses a pattern, what is the scope of the block: exact wording, semantic pattern, context, evidence set, or category?
18. When later explicit user speech appears to contradict a suppression, what should determine whether the memory may be re-created?
19. When an observation decays, should its evidence remain retrievable in provenance, remain available for reactivation, or become inaccessible to generation?
20. When a correction invalidates a memory already used in prior replies or actions, should Kivi expose the affected history, repair downstream state, or only change future behavior?
21. When two sources contradict but neither is clearly newer or authoritative, should Kivi store both as disputed, ask within the weekly confirmation budget, or abstain until relevant?

### User cost and failure cost

22. When several uncertain memories compete for a limited confirmation budget, what should determine “highest value”: expected reuse, expected harm, uncertainty reduction, user irritation avoided, or recency?
23. When a wrong memory would alter an external work action—such as rescheduling—what threshold should separate autonomous execution, confirmation, and abstention?
24. When showing provenance would expose another person’s personal content, how should Kivi remain attributable without redisclosing material it promised not to retain?
25. When a user edits a memory into a claim unsupported by transcripts, should Kivi display it as user-stated, user-authored metadata, or corrected fact?
26. When memory inspection itself becomes a psychological profile by aggregation, what views, exports, or search capabilities should be limited even though each stored item is individually allowed?

## 5. Evaluation gap

### What the paper measured

It measured **nothing empirically**. The paper reports an implemented Next.js/GPT-3.5 Turbo design probe and enumerates interaction affordances. It provides no participants, procedure, dependent variables, benchmark, quantitative results, qualitative findings, comparison condition, or ablation. The authors explicitly place user studies and trade-offs between implicit and explicit memory management in future work ([§2](https://arxiv.org/pdf/2308.01542#page=1), [§3](https://arxiv.org/pdf/2308.01542#page=3)).

What the prototype demonstrates is narrower:

- memory-like context can be represented as visible objects;
- those objects can be toggled, added, edited, deleted, reordered, summarized, and shared through the described UI;
- original conversation can be opened from a summary;
- referenced sharing can preserve an indication of source.

These are capability demonstrations, not evidence of effectiveness, usability, faithfulness, safety, scale, or better conversational outcomes.

### Decisions its evaluation cannot distinguish

Because there is no evaluation, **every pair of defensible answers in the inventory would receive the same reported score: no score at all**. More specifically:

| Indistinguishable alternatives | What evidence would be needed, but is absent |
|---|---|
| Direct manual control vs automatic memory with correction affordances (D1) | Task success, management time, correction rate, mental-model accuracy, long-term abandonment. |
| Conversation fragments vs atomic typed beliefs vs episodes (D2, D13) | Extraction accuracy, user comprehension, correction locality, provenance fidelity, downstream answer/action accuracy. |
| Exact shared representation vs staged trace of retrieved/withheld/used items (D3, D19) | Faithfulness tests connecting displayed objects to prompt inclusion and causal output influence. |
| Visibility gating vs retrieval gating vs disclosure gating (D4) | Leakage tests, counterfactual generation tests, usefulness under each permission mode, user calibration. |
| Overwrite/delete vs supersession/tombstones/suppression (D6, D7, D17, D22) | Longitudinal replay, audit recovery, re-derivation tests, stale-memory recurrence, correction persistence. |
| User-selected summaries vs automatic or structured consolidation (D9, D10) | Information retention, contradiction preservation, source traceability, hallucination rate, user effort, token/latency cost. |
| Copy-by-reference vs snapshot vs global retrieval (D11, D12) | Edit/delete propagation, conflict behavior, cross-context leakage, version consistency. |
| Retain-first/delete-later vs hard write-path exclusions (D14, D15) | Sensitive and third-party retention precision/recall, audit-log leakage, adversarial edge cases, user trust after inspected examples. |
| Per-turn vs batch vs explicit-save extraction (D16) | Capture latency, false-memory rate, cost, missed distributed evidence, correction timing. |
| Newest-wins vs confirmation vs disputed coexistence (D17) | Contradiction datasets with temporal/source ambiguity and harm-weighted outcomes. |
| Embedding vs structured vs hybrid retrieval and alternative ranking rules (D18) | Recall/precision by memory type and tier, temporal robustness, latency, cost, distractor sensitivity. |
| Guess vs clarify vs abstain with near matches (D20) | Answer utility, hallucination/harm rate, recovery time, user confidence calibration. |

| Persistent vs decaying observations/hypotheses (D22) | Longitudinal stale-belief surfacing, adaptation after user change, missed useful patterns. |
| Uniform access vs structural least privilege for dictation/Hey Kivi (D23) | Cross-surface leakage tests and surface-specific task quality. |
| 2D canvas vs tiered list vs response-local Why panel (D24) | Discoverability, comprehension, time-on-task, scale behavior, accessibility, mobile/text-client usability. |
| Cheap conversational repair vs downstream action repair (D25) | Traceability of affected actions, recovery success, external-harm severity and remediation burden. |

### Bottom line for transfer

The paper supplies a useful vocabulary of **interaction possibilities** and a precedent for treating memory as inspectable and manipulable. It supplies no comparative evidence for choosing among Kivi’s write-path policies, epistemic tiers, retrieval design, permission semantics, contradiction handling, decay, abstention, or anti-regrowth mechanics. On those decisions it is precedent only, not evidence.
