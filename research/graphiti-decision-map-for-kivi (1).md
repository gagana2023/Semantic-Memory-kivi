# Inverting Graphiti: a decision map for Kivi

## Scope and reading conventions

**The supplied paper is a query-verification paper, not a semantic-memory architecture.** This document analyzes *Graphiti: Bridging Graph and Relational Database Queries*, Yang He, Ruijie Fang, Isil Dillig, and Yuepeng Wang, arXiv:2504.03182v1, 4 April 2025. It checks equivalence between Cypher and SQL queries under an explicit mapping between databases. It does not describe ingesting conversations into a memory graph. No other system named Graphiti has been substituted. [Paper, §§1–2][p1]

**Kivi source:** the attached *The Things Kivi Comes to Know: A position on semantic memory for Kivi*, filename `kivi-semantic-memory-position (1)(1).md`. References such as **K§6** and **K Appendix B** point to sections of that attachment. The document assumes a text client with replayed transcripts and application context; this analysis does not introduce speech-recognition requirements.

Kivi already commits to category exclusions, non-retention of third-party personal content, explicit promotion, separate dictation access, disclosure permissions, attributable beliefs, abstention, and correction with suppression. These are constraints here, not recommendations to reconsider them. Storage, retrieval, extraction timing, thresholds, cost, and latency remain open in K Appendix B.

**Labels:**

- **F** = load-bearing choice. Its alternative changes the formal guarantee, supported workload, or interpretation of reported results. Section 2 separates demonstrated effects from counterfactual reasoning.
- **Explicit** = the paper describes a choice or rationale. **Inferred** = a choice reconstructed from its formalization or experimental setup.
- **Alternative** means a defensible different problem formulation or implementation. Unless marked **discussed**, the paper does not compare it; it is not an experimentally rejected option.
- **Underspecified** means important implementation or product behavior is not established by the paper. **Outside scope** means it is absent from the problem the authors define. Absence does not establish a hidden implementation.

The inventory excludes mechanical consequences of a chosen semantics. Once faithful Cypher translation is the contract, silently turning an optional match into a mandatory match is a bug, not a defensible design alternative. The choices are the contract, the supported semantics, and the mechanism used to preserve them.

## 2. FORCED CHOICES

These are choices that materially determine what the results mean. A flag is not a recommendation to copy the paper's answer.

| IDs | Why the answer is load-bearing | What is demonstrated, and what is only inferred |
|---|---|---|
| D01–D02 | Equivalence is conditional on both an admissible domain and the chosen mapping. Changing either changes the proposition being checked. | **Formal dependency:** Definitions 4.3–4.6 quantify over transformer-related instances. A mapping that leaves out Kivi-specific state cannot make equivalence of that state part of the theorem. This is not an empirical ablation. [§4.2][p42] |
| D07 | Preserving duplicate counts catches errors that set equality would erase. | **Concrete example:** the motivating queries return the same concept identifier but counts 2 versus 4. A set-of-identifiers contract would accept them. This matters to Kivi whenever evidence counts can be inflated by multiple paths to the same transcript. The latter is a Kivi inference, not a tested paper result. [§2, Figure 4][p2]; [Appendix C][pC] |
| D08, D16 | Expressiveness and proof strength determine which queries can receive which guarantee. | **Measured:** Mediator supports 196/410 pairs and verifies 152; unsupported aggregation/outer joins and unresolved invariants limit coverage. BMC searches more broadly but does not prove unbounded equivalence by failing to find a witness. [§§6.1–6.2][p61] [p62] |
| D09–D10, D13 | The SQL reduction relies on a simple induced representation and residual mapping; changing them changes the proof construction. | **Formal dependency:** Theorems 5.7–5.10 and Appendix F support this construction. No ablation establishes that it is faster than every direct encoding or alternative intermediate schema. [§§5.1–5.3][p51] [p52] [p53]; [Appendix F][pF] |
| D17 | Search budget changes how much “not refuted” means. | **Measured:** bounded search reaches average table bound 19.6 for unrefuted cases; two errors remain in the 50-case manual audit. A different budget can change found bugs and achieved bounds. The size of that effect is unmeasured. [§6.1][p61] |
| D21 | Benchmark composition determines the apparent coverage and verification rate. | **Measured denominator:** 100 supported pairs are from Mediator and 94 from GPT-Translate; only two supported pairs come from the other categories. Therefore the headline proof percentage is dominated by those sources. It is not a workload-independent success probability. [§6, Table 1][p6]; [§6.2, Table 3][p62] |
| D23 | Data shape and the manual-runtime-based scale rule determine the performance comparison. | **Measured under one setup:** 45 mock workloads produce the reported slowdown proportions. Different shapes or scale policies could change those proportions; the paper does not quantify how. [§6.3][p63] |

**What is not a forced choice:** using the wrong join direction, dropping a binding, or replacing existence with multiplicity-producing expansion under the same semantics. Appendix D identifies these as translation bugs. A defensible alternative must change the abstraction or implementation while preserving its own declared contract. [Appendix D][pD]

| K16 | When a relevant memory changes during extraction or answer generation, which version should the response and Why panel reflect? | One request snapshot; latest confirmed state at generation; recheck before disclosure when a relevant revision arrives. | K§8 allows inline correction and K§9 promises auditable supersession. A response and its displayed source must refer to an intelligible version relationship. |
| K17 | When several uncertain memories compete for a scarce confirmation prompt, what should determine priority? | Expected saved re-explanation; current-request relevance; uncertainty and consequence; age among similarly useful candidates. | K§8 caps prompts and attaches them to natural moments. K Appendix B leaves budget and thresholds open. |
| K18 | When a recall query finds no adequate support, what should determine how much near-miss evidence the abstention exposes? | Closest relevant alternatives; a minimal search summary; an expandable account governed by the same permission rules. | K§8's abstention example explains nearby results, while K§6 limits disclosure. Explanatory usefulness and permitted exposure must be reconciled. |
| K19 | When a pattern is no longer observed, what should determine whether it decays? | Elapsed time; missed opportunities to observe it; a combination of time and activity. | K§9 requires decay; lack of observation during inactivity differs from evidence of changed behavior. The decay window is explicitly open. |
| K20 | When a work fact changes, what timing should determine its availability to the next request? | Per-transcript synchronous extraction; batching; immediate handling of explicit corrections with later background extraction. | K Appendix B leaves timing and latency open; K§§3, 8 expect remembered reschedules and cheap corrections. This creates a freshness/cost choice absent from snapshot equivalence. |

These are questions for the spec, not proposals to replace the attachment's commitments. In particular, silently promoting observations, retaining excluded personal content, treating silence as confirmation, or letting dictation load observations are not included as defensible alternatives: the attachment already rules them out.

## 5. EVALUATION GAP

### What the paper measured

| Evidence | Reported result | What it establishes | What it does not establish |
|---|---|---|---|
| Bounded checking, 410 pairs | 34 refutations; 23.4 seconds mean time to a counterexample; remaining 376 reach mean symbolic table bound 19.6. [§6.1, Table 2][p61] | Concrete disagreement exists in the refuted cases; no disagreement was found within achieved bounds for the others. | Unbounded equivalence of the 376; production error probability; a bound of 19.6 for every query. |
| Manual audit | All 34 witnesses judged true positives; 2 incorrect translations found among 50 unrefuted pairs. [§6.1][p61] | BMC missed some real errors within its budget; the audited witnesses were valid. | A general 4% false-negative rate across all faulty queries, or a 4% Kivi failure rate. The audited denominator is unrefuted pairs, not all actual bugs. |
| Deductive checking | 196 supported; 152 verified; 44 Unknown; reported average runtime 16.8 seconds. [§6.2, Table 3][p62] | Proof for supported, verified cases under the modeled contract and backend assumptions. | Proof for the remaining 258/410; refutation when the backend says Unknown; support for aggregation and outer joins. |
| Translation speed | All 410 translated; mean 6.3 ms, median 3.0 ms, maximum 180.2 ms. [§6.3][p63] | Fast compilation on these queries. | Fast query execution, fast end-to-end memory responses, or universal Cypher support. |
| Generated SQL execution | 45 mock workloads; mean 2.2 s generated versus 2.0 s manual; generated faster on 33.3%, at most 1.2× slower on another 51.1%, over 1.2× slower on 15.6%. [§6.3, Table 4][p63] | Runtime observations for this selected workload and scale procedure. | Graph versus relational storage superiority; Kivi tail latency; extraction, update, permission, or replay costs. |
| Comparator | OpenCypherTranspiler: 284 unsupported, 2 syntax errors, 2 semantic errors, 122 correct out of 410. [Appendix E, Table 5][pE] | Coverage and observed translation failures for that comparator and corpus. | An equally broad verified alternative is impossible; Graphiti is the best memory architecture. |
| Formal results | Translation soundness/completeness for the specified grammar; reduction soundness/completeness conditional on corresponding SQL-checker properties. [§§5.2–5.3][p52] [p53]; [Appendix F][pF] | Mathematical relationships under the paper's definitions. | A complete practical decision procedure for unrestricted SQL/Cypher, or end-to-end Kivi correctness. |

### Which choices the metrics cannot distinguish

“Same score” below is conditional on the stated controlled comparison. Where the paper never runs a component, the issue is **no measurement**, not proof that two implementations would perform equally.

| Decision(s) | Two different answers that the evaluation cannot resolve | Why they tie, or why there is no observation |
|---|---|---|
| D04; K01–K03 | Admit the same final work facts via a compliant transient path versus a path that also retains prohibited raw content elsewhere. | If queried tables are identical and the extra retention is unobserved, all query-equivalence outcomes can be identical. Retention behavior is unmeasured. Kivi's non-retention claim remains outside the evidence. |
| D02–D03, D13 | A mapping preserving source/tier/suppression metadata versus one mapping only business values. | If compared queries do not expose metadata, their result equality can be identical under the respective mappings. The checker verifies the supplied contract; it does not judge its completeness for Kivi. |
| D05; K05–K06 | Correct entity resolution versus an incorrect merge already present in both input representations. | Both queries can agree on the same wrongly resolved data. Equivalence is not factual accuracy. No entity-resolution ground truth is evaluated. |
| D07; K04 | Count independent transcript evidence versus count duplicated derivation paths. | The equivalence checker can detect a difference **if** the two query results differ in count. If both implementations make the same counting mistake, they still pass. The paper gives no gold standard for independence of Kivi evidence. |
| D07, D19 | Preserve exact field names versus consistently rename columns. | Definition 4.4 deliberately allows column bijections. Those alternatives are equivalent under this contract even if a consuming API depends on particular field names. |
| D11–D12 | Equivalent `IN`, `EXISTS`, semijoin, or optimized-plan implementations. | Same semantic verdict when equivalent. Execution timings could distinguish them if compared, but the paper does not perform that controlled strategy comparison. It supplies a precedent, not a ranking of these choices. |
| D14; K18 | Explain an empty result as genuinely absent versus withheld or expired. | The same empty table or null may arise under different product states. The evaluated table contract does not include Kivi's explanation, so the product distinction is unmeasured. |
| D15; K15 | Embedding candidates versus exact or hybrid candidates with the same final selected rows. | No retrieval relevance task, recall labels, or reranking study exists here. Query ordering support is not evidence about ranking quality. End-to-end retrieval costs also remain unmeasured. |
| D16–D17 | A truly equivalent query pair versus a faulty pair whose first counterexample exceeds the achieved bound. | Both receive non-refutation at that bound. This is not merely hypothetical: the manual audit finds two missed faulty pairs. A bounded result does not choose between them. |
| D16 | An equivalent pair beyond Mediator's inference ability versus a non-equivalent pair. | Both can return Unknown. The paper identifies two Unknown cases that BMC refutes. Unknown is not a negative proof. |
| D18–D19; K09–K11 | The same visible result with a compliant permission trace versus silent influence from withheld observations. | Output equality can be identical. The evaluation does not inspect generation influence, per-request authorization, or user comprehension. |
| D20; K07–K08, K16 | A correction that survives replay versus one that appears to work until the next extraction rebuild. | Identical immediate snapshots can produce identical query results. No correction/replay sequence is evaluated. The paper offers no evidence about suppression durability. |
| D20; K12, K19 | Different hypothesis-expiry or observation-decay policies that happen to yield the same snapshot today. | Current results can match; future histories diverge. No temporal memory-policy experiment distinguishes them. |
| D21–D22; K17–K18 | A prompt/abstention policy that minimizes interruption versus one that exposes more uncertainty at greater user cost. | No prompt-budget, task-completion, abstention-quality, or user-effort metric is collected. Neither is empirically preferred here. |
| D23; K20 | Synchronous extraction versus batched extraction yielding the same eventual database. | Compilation and SQL runtime on constructed databases omit time-to-memory and correction freshness. The eventual tables can match while interaction behavior differs. |

Sources for equivalence-related ties: [§4.2][p42]. Sources for bounded and Unknown ambiguities: [§§6.1–6.2][p61] [p62]. Sources for the measured workload boundary: [§6][p6], [§6.3][p63]. Kivi-specific distinctions derive from the cited attachment sections in Section 4.

### Important underspecification

- **Operational handling of unsupported input:** the supported fragment is stated, but a production policy for rejection, fallback, partial checking, and user messaging is underspecified. [§8][p8]
- **Backend orchestration:** the two backends are evaluated separately; an automatic portfolio's scheduling and result-combination policy is underspecified. [§§6.1–6.2][p61] [p62]
- **Mapping assurance:** author-written transformers and author effort are reported; independent specification validation and handling of contradictory/inadequate mappings are underspecified. [§6][p6]
- **Runtime reproducibility in the reported experiment:** mock-data distribution details, cache controls, repeated-run uncertainty, and some engine/configuration details are underspecified in §6.3. These cannot be filled in from the supplied paper. [§6.3][p63]
- **Benchmark generation:** GPT-derived pairs are described, but a complete model/prompt/reproducibility protocol is underspecified in the evaluation text. [§6][p6]
- **Formal presentation details:** §4.1 describes transformer satisfaction with implication rules while also using functional transformation notation. If relying on exact transformation semantics, whether this denotes precisely generated target facts rather than merely a satisfying target needs careful resolution. This document does not repair that specification. Likewise §3.1's edge-set notation and unique edge-key assumptions deserve clarification before importing multiedge behavior. [§4.1][p41]; [§3.1][p31]

The paper provides evidence about translating and checking a specified query contract. It provides no measured preference among Kivi's open retention, disclosure, retrieval, confirmation, or lifecycle policies.
